# 运行状态失效事件

失效事件补齐运行视图的可观察性，同时不引入第二事实源。

## Invalidation Events Carry No Workflow State

### 风险

若失效事件携带工作流状态，事件流与数据库读取之间出现排序义务与第二事实源；事件丢失或乱序
将导致前端显示与持久化状态永久分歧。

### 前置状态

- 一个进行中的 run。
- 前端已订阅应用事件流。

### 触发

调度波提交任一 run/node-run 状态转移事务。

### 必须成立

- 事件在事务提交后发布，只标识"哪个 run 的持久化状态已变化"，不携带节点状态、输出或变量。
- 事件丢失或乱序只导致一次过期视图，下一次事件或手动刷新即收敛到数据库真值。
- Agent 输出的实时流不经此通道（仍走 ACP session 流）。

### 禁止结果

- 事件携带节点状态、输出、变量池值或任何工作流负载。
- 前端以事件负载作为渲染事实源。

### 验证义务与证据

| 验证义务 | 代表性证据测试 | 状态 |
|---|---|---|
| 状态转移事务提交后发布不含工作流状态的失效事件 | 尚无直接证据（`AppEvent` 尚无工作流变体） | `Missing` |
| 事件丢失后重查收敛（无第二事实源） | 尚无直接证据 | `Missing` |
