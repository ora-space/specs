## Editing the third item must preserve the ordered prefix

### 风险

将 UI 的第 3 项错认成索引 3，或仅按成员定义匹配，会重复执行有效前缀。

### 前置状态与触发

冻结 [a,b,c,d,e]；前两项已结算，旧 Agent 在第三项 c 挂起。选中该尝试，让成员给项值加 new-。

### 必须成立

旧、新尝试均读到 c；同一容器执行从 index=2 起沿用新配置，汇总按原序各一项。

### 禁止结果

前两项重复调用，或晚到的旧 c 覆盖新项账。

| --- | --- | --- |

| 释放旧尝试的迟到回报，重开详情。有效 output 为 [a,b,new-c,new-d,new-e]；entries 按原序共五条、失败数 0，旧尝试仍可回看。 | — | Missing |
| 全部五项成功后再回选第 3 项，累计调用 [1,1,2,2,2]。第 3–5 项的旧账与旧汇总退出当前投影。用重复项值复测，索引仍能区分两项。 | — | Missing |

## Rerouting a condition must withdraw the old branch from the join

### 风险

A 的旧变量残留会让优先读 A 的汇合忽略 B 的新输出。

### 前置状态与触发

Start.flag=true，A 为原 IF、B 为 ELSE，J 依序读取 A、B。旧 J 已读 a，独立 S 已完成。将 c1 的比较值改为 false。

### 必须成立

### 禁止结果

### 验证义务与证据

## Resuming a while member must use the selected round

### 前置状态与触发

### 禁止结果

## Changing a container must rebuild it from its entry

### 风险

### 前置状态与触发

### 禁止结果

用旧账凑新汇总，将旧成员覆盖带入直接或上游触发的重建。

## A ready unstarted node must enter normal scheduling

### 风险

给未派发目标伪造执行 ID，或绕过依赖，会导致重复派发。

### 前置状态与触发

Running 的 P 中 Start 已提交 hello。“已就绪、尚无行”是瞬时状态。测试在 Start 的提交完成后、调度器首次认领 X 前设置可释放的屏障；在屏障处打开表单，使用 D1 的 pendingTarget；另准备已登记执行行的退避重试。

### 必须成立

逻辑位置在首次正常派发时才绑定真实尝试；已有退避行用 nodeRunId。

### 禁止结果

预览时写节点行、无前置就派发，或把已有退避行当作空位置。

### 验证义务与证据

| 验证义务 | 代表性证据 | 状态 |
| --- | --- | --- |
| 表单提交 rootP/rootP/X；预览不创建执行行。确认后释放屏障，由普通就绪门首次派发，恰好一个真实尝试绑定新修订并收到 hello。 | — | Missing |
| 分别缺少 Start 的输入、缺少可唯一识别成员的作用域。前者报告缺少的前置值，后者指出缺少的位置字段。两者均无可确认凭据、无派发。 | — | Missing |
| 在抢先派发变体，预览后先释放屏障并等 X 建行，再确认返回 stale_preview，原尝试继续，额外修订和调用均为零。未启动的 Pending 运行使用原编辑/启动入口。 | — | Missing |
| 退避已登记的重试按有效 nodeRunId 预览，不能再用 pendingTarget 重复认领。逻辑位置首次正常派发后，从历史的原操作和位置可查到同一实际 nodeRunId。 | — | Missing |

## A top level edit must be private to its run and preserve history

### 风险

运行内调试可能误开整个终态运行、污染其他运行或将旧补丁带入新快照。

### 前置状态与触发

两个 run 绑定同一快照。在其中一个根 Agent X 上先改模型，再改提示词。在 Failed、Cancelled 和 Succeeded 的运行里复测；另从普通恢复入口切换兼容快照。

### 必须成立

修订和生效范围可追溯。终态 run 仅在用户确认的调度边界内执行，最终状态由全部当前事实决定。

### 禁止结果

范围外已取消的行复活、独立未派发位置被启动、只按局部成功就宣告全 run 成功，或切换后重放旧补丁。

| --- | --- | --- |

| 按请求键重查能找回各操作；失效尝试可查实际配置及替代关系。另一 run 和发布快照保有原配置。取消编辑时修订、调用数均不增加。 | — | Missing |
| 分别从 Running（含 AwaitingInput）、Failed、Cancelled、Succeeded 选择证据齐备的目标，均可预览确认；已终结 run 在同一 ID 下继续。 | — | Missing |
| 分别设置范围外 Failed、Cancelled 的终态行；确认及范围内结算后再次查行，其状态和尝试 ID 均保留。 | — | Missing |
| 范围外放置一个从未派发且依赖已齐的独立节点。终态 run 调试全过程该节点调用数为零，也没有创建执行行。 | — | Missing |

| 先使顶层 X 的新提示词生效，令该 X 的某次尝试失败后走普通失败恢复。恢复沿用当前有效修订及其提示词，仍按原选点和工作区策略派发。 | — | Missing |
| 同一 run 同时有顶层模型修订和旧容器第 3 项起的成员覆盖。整次运行重启后根 ID 更新，顶层仍用新模型，新容器各项按入口成员配置执行。旧根的覆盖及尝试可从历史查询。 | — | Missing |

## Confirmation must fence retries and survive restart

### 风险

确认、取消、启动清理或迟到回报争用同一次执行，可能多派发或将旧轮记入当前账本。

### 前置状态与触发

挂起一个旧 Agent 和延迟重试，另留独立在途兄弟及它写入的文件。分别交错预览、自行结束、确认、整 run 取消和进程重启。

### 必须成立

认领先验证读集并封住受影响范围。旧请求可重查；停稳失败可解释；重启按持久操作和最新取消事实恢复。

### 禁止结果

启动清理越过栅栏写失败账、释放栅栏后按旧配置自发重派，或以晚到停稳回报复活已取消的 run。

### 验证义务与证据

| 验证义务 | 代表性证据 | 状态 |
| --- | --- | --- |
| 目标输入、未赋值状态或受影响尝试集合变化时，旧预览返回 stale_preview，零停止、零修订。仅独立兄弟推进且读集相同，原预览可确认。 | — | Missing |
| 同键同凭据双击只受理一次，同键异凭据报冲突；并发确认最多一个生效。客户端断连或漏收通知后读回同一操作与阶段。 | — | Missing |
| 无法证明在途外部写入已隔离时，记录 stop_failed、具体尝试和实际停止结果，受影响范围零新修订、零新派发。兄弟仍可提交。解除阻塞后新凭据与新键才能再试。 | — | Missing |
| 在停稳中及生效后尚未派发时分别重启 Desktop 进程。持久操作最多生效一次；显式释放旧回报、重试或人工确认，记录其到达，新变量和下游调用数均不受影响。 | — | Missing |

## Missing provenance and invalid patches must block precise resume

### 风险

把最后一次池值当作历史输入，或向缺失字段写 replace，会让预览承诺不可重放的计算。

### 前置状态与触发

存量 run 仅保留最后一项池值。用完整历史另测越界变量、无效模型、嵌套数组源及不属于此 run 的目标。

### 必须成立

错误能定位到缺失证据、选择位置或字段。只有可证明的新入口才允许独立预览。

### 禁止结果

伪造历史输入、把缺失叶子当作 replace 新建，或自动扩大执行范围。

### 验证义务与证据

| 验证义务 | 代表性证据 | 状态 |
| --- | --- | --- |
| 分别返回具体缺失事实或字段路径，无可确认凭据、无修订、无派发。缺少关联的历史行返回未知修订和未知配置，不能以当前快照倒填。 | — | Missing |
