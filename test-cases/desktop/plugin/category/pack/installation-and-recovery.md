# 插件集合包的安装、恢复与整体卸载

决策依据为已批准的
[Plugin Pack 根决策](../../../../../decisions/desktop/plugin/category/pack/0-plugin-pack.md)。
用例按生命周期风险组织；当前无 pack 直接证据，表中列出待验证义务而非虚构测试名称。

## Preflight and Local Preparation Must Precede Every Member Installation

**风险**：成员先安装，pack 创建失败后失去生命周期归属；无效计划在下载中途才被发现。

**前置状态**：一个未安装的 pack，可注入重复、自引用、缺失、嵌套或待安装成员 host 不兼容；
另有合法计划但 pack 清单复制、目录创建或初始记录写入失败的情形。

**触发**：通过生产安装入口安装 pack。

**必须成立**：preflight 失败无制品请求、安装树不变；本地准备失败不启动成员安装。合法计划先
持久化 pack 安装态和记录，再安装成员；前端在整体提交前显示安装中，pack 自身无制品请求。

**禁止结果**：跳过校验、下载 pack、静默接受非法计划或在 pack 本地创建前提交成员。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| preflight 拒绝全部上述无效计划，网络与文件系统副作用为零 | 待生产入口加故障源与安装树快照验证 | `Missing` |
| 本地准备失败不启动成员，合法准备先于成员副作用 | 待注入复制/记录失败，并观察持久化与下载调用顺序 | `Missing` |
| 物理 pack 落盘不提前报告成功 | 待暂停成员安装后验证契约与前端安装中状态 | `Missing` |

**决策依据**：D1、D4；不变量 1、3。

## Only Same Namespace Installed Members May Be Skipped

**风险**：跨源同名被误认为已装，或 V1 安装悄悄升级既有成员并认领其归属。

**前置状态**：pack 在源 A，部分成员在 A 已装旧版或新版，另有只在源 B 已装的同 identifier
插件；A 中已装成员的 registry 新版可无当前平台资产。

**触发**：安装 pack，随后成功卸载或失败回滚。

**必须成立**：仅同一 canonical ID 的任意已装版本跳过，原版本与归属不变；A 未安装而 B 已装
时仍从 A 安装。跳过成员不因 registry 新版资产不兼容失败，也不进入新增成员或删除集合。

**禁止结果**：跨源兜底、升级/降级被跳过成员、从源 B 下载 A 的成员或卸载用户预装插件。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 同 ID 任意版本跳过，跨 namespace 同名不跳过 | 待双源安装入口与不同版本基线验证 | `Missing` |
| 跳过成员无下载、无新增归属，回滚与卸载不改动它们 | 待观察完整安装记录、原版本及清理后状态 | `Missing` |

**决策依据**：D2、D4、D8；不变量 4、5。

## Pack Success Requires Durable Ownership of Every Newly Installed Member

**风险**：返回成功时登记不全，或安装后清理 staging 导致整体卸载丢失依据。

**前置状态**：计划混合缺失成员与预装成员；成员采用不同单插件 outcome，期间 registry 可刷新。

**触发**：完成 pack 安装，再重建宿主并读取安装状态。

**必须成立**：按固定计划和声明顺序执行；成功或跳过全部成员后才提交整体成功。成功记录位于
pack 身份目录的 `staging/`，保存全部新增成员的 ID、版本和归属，重启后可读取；跳过项只作
过程记录。契约保留逐成员 outcome，包括命令别名冲突，前端成功与持久化结果一致。

**禁止结果**：返回部分成功的 `PackInstalled`、混用刷新后的成员计划、把记录放 `data/` 或
版本目录、成功后删除登记。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 重启后完整登记与实际新增集合一致，顺序及所选 release 不受刷新影响 | 待持久安装和源变更集成验证 | `Missing` |
| 聚合结果与单插件 outcome 完整，成功通知发生在持久提交后 | 待 typed handler 前端验证及 backend 提交边界故障注入 | `Missing` |

**决策依据**：D4、D6；不变量 6、7、13。

## Exhausted Retries Must Roll Back New Members Before Removing the Pack

**风险**：重试耗尽留下成员孤儿，或清理失败却删除唯一归属记录、向用户报告成功。

**前置状态**：先有新增成功成员，后续成员可暂时失败或持续失败；清理某个新增成员也可失败。

**触发**：推进重试至成功或耗尽，再在待清理状态重建宿主继续恢复。

**必须成立**：重试有界且不重复安装已成功成员；耗尽后不尝试后续成员。按提交逆序清理本次
新增成员，一个清理失败不阻塞其余项；全部新增成员移除后才删除 pack 和记录。未完成时保留
`rollback_pending` 与待清理项，恢复后继续。前端区分安装失败已回滚与安装失败待清理，并保留
原始安装错误和回滚错误；本次剩余待执行成员可辨。

**禁止结果**：无限重试、把待清理报告为已回滚、先删 pack、误删预装插件或只记录日志不通知。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 可重试失败成功恢复；耗尽或不可重试失败停止后续成员并逆序补偿 | 待注入失败类别并观察尝试次数、调用顺序和磁盘结果 | `Missing` |
| 清理失败保留 pack 与记录，重启后完成剩余清理且最后移除 pack | 待卸载/删除故障与跨宿主恢复验证 | `Missing` |
| 前端收到已回滚或待清理的准确失败结果，包括恢复后的结果 | 待生产契约与 typed handler 通知验证 | `Missing` |

**决策依据**：D4–D6；不变量 9、10。

## Cancellation and State Write Failures Must Preserve Compensation

**风险**：用户取消或成功记录写盘失败时，内存任务结束但新增成员仍无最终归属。

**前置状态**：至少一个成员已提交；下一成员正在下载/重试，或全部成员完成但整体成功记录未提交。

**触发**：取消安装，或使下一次状态写入失败；随后重建宿主。

**必须成立**：取消进入补偿，成功记录写入失败不发布成功；记录失败后停止新安装副作用，最后
有效记录仍可恢复清理。取消请求不取消必要补偿，宿主退出后由持久记录继续；前端收到真实失败
及清理状态。

**禁止结果**：取消清理责任、返回成功、丢弃最后记录或把未登记的已提交成员当成用户预装插件。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 下载或重试中的取消移除本次新增内容并保留预装基线 | 待在真实异步边界取消并观察补偿 | `Missing` |
| 状态写入及最终提交失败不报告成功，重启仍可补偿 | 待持久存储失败注入与重建宿主验证 | `Missing` |

**决策依据**：D5、D6；不变量 7–10。

## Recovery Must Reconcile Commits Without Resetting Retry Budgets

**风险**：成员提交与写结果之间崩溃，恢复时漏认领或误认领；每次启动重置重试次数造成无限安装。

**前置状态**：记录处于 preparing、成员 installing/retry_pending、整体 rolling_back 或
uninstalling，可在副作用前后中断；源内容在中断期间可能变化。

**触发**：在 pack 创建、成员提交、成员结果写入、成员删除及 pack 删除的边界终止宿主，再启动
恢复；对同一状态重复执行恢复。

**必须成立**：用操作 ID 与安装实例核对已提交内容，依持久阶段恢复，不凭 ID 存在猜归属。
准备完成前无成员副作用；原计划和已用预算保持，已提交或已清理项不重复产生副作用。成员清完
且 pack 已删但记录仍在时可完成最后收尾，不重新创建成员。

**禁止结果**：重复认领、丢失登记、每次恢复重新下载已提交成员、刷新计划或重置重试预算。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 提交与登记窗口以及删除窗口均可核对，重复恢复幂等 | 待各持久边界中断并在新宿主实例恢复验证 | `Missing` |
| 计划及重试预算跨重启不变，prepare 未完成不安装成员 | 待跨重启计数、源变更及阶段观察 | `Missing` |

**决策依据**：D4、D6、D8；不变量 1、8–11。

## Concurrent Operations Must Not Share or Steal Member Ownership

**风险**：两个 pack 同时安装一个成员，或独立操作替换成员后，被另一个事务回滚误删。

**前置状态**：两个 pack 共享同源缺失成员；另有同 pack 的安装/恢复/卸载请求和成员独立安装/
卸载/更新请求，均可在基线检查与提交之间交错。

**触发**：通过实际领域接口并发执行上述操作，再使一个 pack 失败或卸载。

**必须成立**：同 pack 事务互斥；成员只有实际提交方取得归属，另一方重新检查后跳过。实例
变化不能在归属核对与删除之间穿透协调边界；恢复不认领其他操作的提交。

**禁止结果**：双重认领、相互覆盖状态文件、死锁导致事务无法收尾或删除其他操作拥有的实例。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 两 pack 竞争同成员只产生一个归属，失败方不误删另一方提交 | 待用可控 barrier 在生产接口制造交错 | `Missing` |
| 同 pack 互斥且成员独立操作无法穿透检查/提交/删除边界 | 待安装、恢复、卸载和独立操作的并发集成验证 | `Missing` |

**决策依据**：D6、D7；不变量 8、9、11。

## Pack Uninstall Must Preserve Unowned and Independently Reinstalled Plugins

**风险**：卸载使用当前成员清单，误删预装插件或已独立重装的同 ID 实例；卸载失败丢失记录。

**前置状态**：成功 pack 有登记成员、跳过成员、已独立卸载成员及之后独立重装的同 ID 成员；
registry 清单已变化，某个实际归属成员的卸载可失败。

**触发**：整体卸载，失败后重建宿主继续清理。

**必须成立**：依据成功登记与当前实例归属清理；已不存在视为清完，独立卸载释放归属，独立
重装不自动认领。成员失败继续清理其余项，保留 pack/记录和失败通知；成员全部处理后才删除
pack 与记录。实例意外替换时保留插件并报告。

**禁止结果**：从当前 registry 重建删除集合、删跳过成员、先删 pack 或将重装实例当作旧实例。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 清单变化、独立卸载/重装与预装基线均不扩大删除集合 | 待通过独立安装/卸载与 pack 卸载接口验证磁盘和归属 | `Missing` |
| 成员清理失败保留可恢复记录，完成后最后删除 pack | 待卸载故障注入、重建宿主与前端结果验证 | `Missing` |

**决策依据**：D6、D7；不变量 11。

## Persistent Staging Must Survive Version Cleanup and Reject Unknown State

**风险**：版本扫描/临时清理删掉持久记录，新布局覆盖既有文件，损坏记录触发猜测性批量删除。

**前置状态**：pack 身份目录有合法 `staging/` 和版本目录；另有同名文件、符号链接、未知目录、
缺失/损坏/未知格式记录，以及旧试验 data 内容与其他插件正常安装。

**触发**：发现插件、退役版本、清理临时目录、启动恢复或尝试新安装。

**必须成立**：`staging/` 不作为 SemVer 版本或临时垃圾处理；合法记录持续可用。未知占用与
无法验证归属的状态被隔离并报告，不覆盖、不递归删除，也不影响其他插件或宿主启动；旧 data
不自动迁移或清空。

**禁止结果**：丢失成功登记、按当前 registry 猜归属、跟随链接操作外部目录或批量删除用户文件。

| 验证义务 | 直接证据与缺口 | 状态 |
| --- | --- | --- |
| 发现及版本/临时清理保留 pack 持久记录 | 待真实安装布局下调用生产发现和清理接口 | `Missing` |
| 路径冲突与异常记录只影响本 pack，不改写未知内容 | 待文件/链接/损坏记录/旧 data fixtures 与启动隔离验证 | `Missing` |

**决策依据**：D6、D9；不变量 6、14。
