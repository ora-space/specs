# 个人连接统一保存，Agent 默认配置按插件解析并在创建运行时冻结

用户在插件“我的配置”中选择个人连接、模型和插件选项；内联新建连接仍写同一个人连接库。Cloud
冻结本次 Agent 执行配置，model-gateway 保管真实 Key，插件只消费运行临时授权。首期增加 Claude
普通 Agent Run，并保留 OpenCode 与工作流 `default` 的既有语义。

本文为 `approved`，记录已批准方案而非已实现能力。范围包含 Cloud 个人配置、运行准入/绑定、
Thread 权限和 Messages 兼容；不实现 Pi、Codex Responses、其他 CLI 或 Claude 工作流节点。
术语见[个人 Agent 配置](../../../domain/glossary.md#personal-agent-configuration)。

## D1：连接与插件配置各有唯一的个人归属

个人连接继续保存协议、上游地址、认证方式、模型目录及不透明凭据引用。插件配置保存自己的
canonical Plugin ID、声明指纹、配置 revision、模型选择与非秘密 Settings；首期每用户每插件
至多一份默认配置，不增加命名 profile 集合或空间共享配置。配置按 canonical Plugin ID 单份
归属，不按发行或声明指纹区分保存：同一用户在多个空间选定同一插件的不同声明版本时，单一
配置至多与其中一个空间的指纹一致；指纹不一致的空间里创建运行明确拒绝并提示原因，引导在
该空间的发行上下文里显式修复，在一个空间修复会使其他空间重新失配。这是首期已知限制，按
声明指纹或发行区分保存多份配置留待后续决策，不通过静默回退某一空间版本掩盖。

归属只来自已认证用户；普通成员和空间管理员均不能读写他人的配置。Space 管理员可安装插件，
不因此获得成员的个人连接或额度。读取个人配置不要求先创建运行 Workspace；使用时仍检查当前
空间资格和选定插件是否可执行。身份从完整 Plugin ID 判定，不按展示名或裸 identifier 合并。

插件页的“选择连接”和“新建连接”复用同一个人连接模块，模型选择来自该连接的目录。API Key
仅通过 Gateway 的专用接口交给 model-gateway；普通 settings 接口不接受或返回原始 Key、密文、
凭据引用、认证头或运行令牌。页面仅展示凭据已配置状态；不导入原生 CLI 的整份配置或登录文件。

保存按资源 revision 与编辑时声明指纹校验；编辑期间发行上下文变化，须重新检查而不是拼接旧字段
与新声明。非法类型、越权引用及版本冲突拒绝并保留用户草稿。配置完整性与模型连通性是独立结果：
字段齐全不证明上游可用，启动门禁仍须检查凭据、模型和执行能力。

声明指纹相同也必须检查配置 revision。两个编辑器从同一 revision 保存时，至多一个不同修改提交
成功；陈旧写入不能自动重试覆盖胜者。首次并发创建只有一份个人配置，清除配置也推进 revision；
重新填写不能复用清除前的 revision。沿用个人资源的幂等约束：同一操作的合法重放返回原结果，不
额外推进 revision，不同输入不能复用同一幂等身份。OpenCode 的模型选择仍按全局默认资源自己的
version 校验，不能拿插件选项 revision 代替它。

## D2：显式 Agent 选择决定默认值来源，不做隐式回退

| 入口 | 模型选择来源 | 缺少或不可用时 |
| --- | --- | --- |
| 普通 OpenCode Agent Run | 现有个人全局默认连接/模型；插件页对此提供同一资源的视图 | 沿用既有缺配置拒绝 |
| OpenCode 工作流 default 槽位 | 同一个全局默认值，槽位规则不变 | 按槽位门禁列出缺口 |
| 显式 Claude 普通 Agent Run | 该用户的 Claude 个人配置 | 拒绝，不取 OpenCode default、作者配置或宿主登录态 |

OpenCode 不另存一份连接/模型默认值。插件专属非秘密选项可有自身 revision，但不能复制并竞争
全局默认选择。Claude 配置保存成功不改变全局 default，选用 Claude 也不会改变工作流槽位的 CLI。
不同来源的同名插件不是同一默认配置，迁移来源必须显式处理。

首期 Claude 使用一个 `anthropic-messages` 连接和一个明确的冻结模型 ID。主模型与所有会产生
模型调用的辅助别名均由 adapter 映射到同一已授权模型。名称相同不等于协议兼容；不能将
`openai-completions` 连接当 Messages，或把 ACP 的供应商标签当平台协议身份。
若固定 CLI/adapter 无法满足单模型约束，则该组合不合格，另经多角色绑定决策；不得自动允许第二
模型、直连上游或静默更换模型。独立小模型的成本优化不在本期承诺内。

## D3：在创建事务中验证并冻结一次执行配置

创建普通 Agent Run 时，Cloud 校验显式 Agent、空间资格、选定发行/声明、配置归属及 revision、
协议交集、连接启用状态、凭据已配置、模型仍在连接目录，以及执行所需的模型代理/adapter 能力。
发行目标还不能确认或平台不支持相应能力时明确拒绝，不能创建永远等待用户补配置的运行。

门禁与持久化运行/评论/交互的原子边界一致：校验失败不残留可派发运行、有效绑定或成功交互。
配置解析只读已验证的持久声明和个人资源，不在 SQL 事务内执行插件、下载或调用模型。
能力检查并不替代实际 Node 安装和启动时的精确身份检查。

新运行冻结的逻辑信息为：

| 组 | 冻结信息 |
| --- | --- |
| 发起者与执行器 | 发起用户、Git 身份、canonical Plugin ID、精确包版本/target/包摘要 |
| 配置契约 | 声明版本/指纹、adapter 契约版本、个人配置 revision、已解析的非秘密 Settings |
| 模型绑定 | 连接及版本、协议/地址/认证方式、不可变凭据引用、模型 ID/元数据 |

这些是服务端生成的事实，不接受调用者提交一个“已验证快照”。运行详情只展示允许共享的执行器、
版本、连接显示名、模型和配置版本；不暴露服务地址、个人 Settings 实值、密钥引用或令牌。
非秘密 Settings 不含凭据不等于可以对其他空间成员公开全部个人选项。

控制输入只传必要的冻结非秘密配置与不透明绑定引用；授权申请仍由 Node 专用证书绑定执行目标。
插件不能自行挑选另一个用户、连接、模型或包。运行内重新启动准备步骤继续用原快照，不能重读
当前默认值；Node 崩溃不恢复原 Agent 会话的既有规则也不因此改变。

## D4：编辑与撤销分开，失效授权不能因重新配置复活

普通 Settings 编辑、模型选择变化、配置清除和 Key 替换只影响新运行；旧运行使用原冻结引用。
清除插件个人选项不级联删除被其他插件引用的连接，也不等于清除连接 Key。用户显式清 Key、停用/
删除连接时，根决策的永久撤销立即适用于所有相关绑定；重新启用或再填 Key 不复活旧运行。

成员/账号失效、结束和取消继续约束授权申请、续期、每次转发及在途流。纯降权操作不依赖部署 DNS
或出口可用，继承共享出网 ADR 的撤销规则。配置更新不热切换 Agent/provider，首期不开放运行中
更换模型；会话内可见选项也不能绕过已冻结模型集合。

Claude Thread 与已有个人模型 Thread 使用同一额度控制：当前有效成员可读取，只有仍有有效资格
的运行发起者可以追加消息；发起者与当前租户管理员可以结束。其他成员不能借协作读取权使用
发起者的模型额度，管理员也不因可结束而获得追加权。成员/账号失效按当前资格拒绝读写；绑定被
撤销后仍有结束权的人可结束，但不能追加。ending/ended 或取消待处理不受理新轮次，有效成员的
历史读取权不变，结束命令的状态与幂等规则继续由 Thread 决策拥有。不能只禁用前端按钮，也不改变
没有个人模型绑定的历史 Thread 权限。

同一插件被卸载时不删除个人连接或设置，当前运行遵守安装租约/维护规则；重新安装后必须重新核对
实际声明身份和配置指纹。不允许卸载重装复用陈旧连接、绕过已撤销绑定或把新版本配置注入旧运行。

## D5：迁移保留旧默认值和历史运行

PostgreSQL 采用追加迁移。既有个人连接、密文引用、OpenCode default 和历史绑定保持原义，不复制
Key、不重算历史运行、不把缺新字段的旧执行自动解释为 Claude。旧版 OpenCode 路线只保持原有
明确兼容行为，不推广为新 Agent 缺声明时的通用回退。

新 OpenCode adapter 就绪后，个人配置页面继续引用原默认选择，既有模型/连接不要求重新输入；
新声明要求的必填选项缺失时仍明确要求用户补齐。新 run 才开始使用新执行配置快照，旧 run 继续
绑定旧发行。对已有包的安装与使用不能通过改写包内文件来完成迁移。

声明指纹不匹配时保留旧值但标为需修复，拒绝保存旧编辑器内容或启动新运行；用户按新声明显式
确认/修复后获得新 revision。不得默默丢弃未知项、自动跑插件迁移脚本或改写在途快照。
包升级但声明字节逐字节相同（声明指纹一致）时可以复用经验证的值，运行仍冻结新包身份；
字节有任何差异——包括仅排版变化——都按指纹不匹配处理并要求显式修复，不存在“字节不同
但兼容”的中间状态，指纹定义见[Agent 声明决策 D2](../../desktop/plugin/manifest/20261017-agent-configuration-declarations.md)。

显式修复不能继续使用旧编辑器的保存条件：重新加载返回当前发行关联/声明指纹、旧配置的指纹与
revision，并将旧值作为待确认数据展示，不把它们直接应用为新配置。用户按新声明提交完整选项和
模型选择，带当前声明指纹及预期旧配置 revision；服务器重新校验当前发行、引用归属、必填项与
类型，再以同一 CAS 原子写入新指纹和新 revision。期间再次升级或有其他修改则冲突，保留草稿。
移除的字段只有经此次显式完整提交才退出有效配置；修复不复制/重写连接 Key，不改变已有运行快照。

## D6：Messages 兼容不变成任意模型代理

首期仍只支持既有 Completions 与 Messages 推理协议。Claude 的 base URL 拼接、固定版本所需
query/非认证协议头及 SSE/工具数据必须在 model-gateway 的明确受限协议规则内实现；不能为通过
某个 CLI 而关闭认证替换、模型比对、TLS、当前授权或部署出网检查。

Messages 的必需推理请求与可选发现/计数请求分别验证。实现须为选定 CLI 版本列出实际允许的
路径、方法、query 和协议头，并证明未知输入拒绝；不能透传任意 URL/头或通过“OpenAI-compatible”
标签自动开放 Responses。可选能力未实现不能伪装成功，adapter 必须在该能力组合下仍满足冻结模型
约束，否则拒绝使用该组合。网关不自动重试生成，统计仍按已登记 HTTP 尝试计算。

供应商宣称或用户确认支持 Messages、流式、工具调用，只能作为验收输入，不等于 Ora 固定插件/
CLI、临时授权、成果和资源释放已贯通。真实证据不得包含生产地址/Key 或以占位模型测试冒充真实
供应商。多协议转换、新认证方式、独立辅助模型、Responses 和多 CLI 工作流另行演进。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 每插件复制连接与 Key | 首次界面直观，但轮换/删除重复，跨插件共享变成另一层同步问题 |
| 每 CLI 专用 Cloud 页面和分支 | 首个接入较快，但以后每个插件升级都牵动核心和界面 |
| Claude 缺配置就用全局 default | 少一次配置，但可能使用错误协议、额度或执行器，破坏显式选择 |
| 配置保存后热切换在途 provider | 更新即时，但使一次运行输入可变并扩大连接级串用风险 |
| 任意模型或全量原生配置透传 | 兼容面宽，但失去授权集合、凭据和平台策略的可判定边界 |

## 不变量、验收与落地

1. 一个用户的连接库只有一个权威，插件配置不拥有长效 Key。
2. 显式 Claude 运行只使用该用户的 Claude 配置；OpenCode/default 不出现第二份选择事实。
3. 每次运行冻结执行器、声明、选项与单模型绑定；普通编辑不能改变它。
4. 已撤销绑定不复活；schema 可渲染、配置完整和上游能力声明均不等于可执行。
5. 个人模型 UI 不能放宽权限、文件、网络或任意进程参数策略。

按声明分发、个人存储/准入、Node adapter/网关、真实验收顺序落地。新行为必须通过
[个人 Agent 配置用例](../../../test-cases/cloud/model-access/personal-agent-configurations.md)，
保留[原个人模型用例](../../../test-cases/cloud/model-access/personal-model-access.md)的覆盖边界。
同插件多份配置（含多空间不同声明的区分保存）、其他 CLI 的多角色模型、账号登录和多 CLI 槽位
不由本期迁移顺带交付。
