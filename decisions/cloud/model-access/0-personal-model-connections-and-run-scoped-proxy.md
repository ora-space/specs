# 个人模型连接由用户配置，平台保管密钥并为每次运行代理模型请求

> 后续决策：[部署方模型出口与显式解析](20261017-deployment-owned-egress-and-explicit-resolution.md)
> 已实现 D5 的企业模式网络边界扩展；非企业模式继续本文的公网规则。新增验证义务和证据
> 由后续决策的核心用例单独维护，不从本文原公网证据推定。

用户在设置页保存自己的模型连接，一组连接包含协议、服务地址、认证方式、多个模型及密钥引用。
OpenCode 的一次运行冻结发起者选择的连接和模型，通过平台模型代理调用上游；沙盒仅取得当前运行的临时凭据。
真实 API Key 不进入 Cloud 服务、Controller、Node 或会话记录。

本决策状态为 `implemented`；证据与缺口见核心用例。
涉及 Cloud 的个人设置、IssueRun 绑定、独立 model-gateway、Node 模型访问及 cluster 部署。
PostgreSQL 采用追加迁移，历史运行没有模型绑定；本决策不承担生产完整进程隔离、计费、思考档位及 MCP 配置。

## 决策

### D1：连接、默认选择和密钥归属于个人

连接及默认模型以已验证的 Cloud 用户为归属，不使用请求体指定的用户、租户或空间身份。
同一人可以保存多个连接，每个连接有多个模型；模型 ID 是不透明字符串，斜线不表示另一连接。
公开读取只返回允许展示的元数据和 `credentialConfigured`，不返回密钥、密文、密钥 ID 或凭据引用。
写入、替换、清除 Key 使用 Gateway 独占的凭据接口，Cloud HTTP 在读取其请求体之前拒绝该接口。

支持 `openai-completions` 与 `anthropic-messages`，可配置 Bearer 认证；Anthropic 还支持 `x-api-key`。
UI 以表单编辑连接和模型列表；不直接导入 Pi 配置，也不声明已验证其思考参数兼容性。

### D2：Cloud 保存业务权威，model-gateway 独占密钥解密

PostgreSQL 保存连接、个人默认值、不可变密钥记录、运行绑定及临时授权摘要。
加密在 model-gateway 中完成，使用 AES-256-GCM：随机 nonce 与密文和认证标签一起保存，认证数据绑定密钥记录 ID。
加密主密钥只以部署引用挂载给 model-gateway，重复启动复用原卷；数据库与主密钥卷必须一同备份。
启动时检查现有密文是否仍可解密；主密钥丢失不能通过生成新密钥静默恢复。

凭据写入继续校验用户状态、连接归属、资源版本和幂等键。幂等比较使用密钥服务计算的带密钥指纹，
不保存原始 Key 的可离线验证哈希，也不使用每次随机生成的密文决定是否为相同重试。

### D3：OpenCode 运行冻结配置，撤销不能复活旧运行

在创建 OpenCode 运行的同一事务中冻结连接版本、密钥引用、模型和发起者 Git 身份。
默认值缺失、连接不可用、密钥未配置或模型已移除时，整条评论及运行创建回滚。
配置编辑或 Key 替换仅影响之后创建的运行；已开始的运行继续使用其冻结引用。
清除 Key、停用或删除连接时，永久撤销既有绑定及授权；重新配置或启用只能用于新运行。
因此不能通过开关连接让一个之前已撤销的沙盒重新获得个人 Key 的使用权。

### D4：临时授权由证书目标和当前数据库状态共同决定

Node 使用专用 model-access 客户端证书申请授权，证书绑定租户、Workspace 和运行代次，
不复用仅承担 WSS 服务端用途的证书。JSON body 只携带绑定与会话执行 ID，不能自行声明认证目标。
Cloud 验证当前 Node、协商能力、会话执行、已确认的运行绑定、维护占用、成员和账号状态。
只有可受理的 `pending` / `active` / `idle` 会话能够获得或继续使用授权。

临时令牌只保存摘要，有效期为数据库时间起 15 分钟；Node 在到期前续期，续期延长同一令牌。
每次请求及流式响应期间重新核验授权，结束、强停、成员/账号失效或显式撤销会取消后续调用和在途转发。
原始令牌只留在运行进程的内存与环境中，不写控制账本或 Git checkout。

### D5：平台代理限定目标和模型，保持协议流式语义

代理只接受 Chat Completions 和 Messages 的 POST，不允许客户端选择转发 URL、认证头或另一个模型。
目标由冻结连接读取，真实认证头由凭据服务加入；模型 ID 必须与运行冻结值相同。
SSE 文本、工具调用及结果持续转发，不等待完整生成，也不自动重试生成请求。
默认目标仅为公网 HTTPS：连接时校验 DNS 结果并直接连接已校验地址，不使用环境代理或跟随重定向。
生产解析由部署明确配置的可信 HTTPS DNS 提供，使用公网数字地址引导并正常验证解析服务的 TLS 身份；
不回退到可能返回 fake-ip 的系统解析。所有 A/AAAA 答案均须通过公网策略，包含 `198.18.0.0/15`
或 `2001:2::/48` 等保留地址时整次拨号拒绝。拨号仍使用验证后的数字地址，上游 TLS 保留原域名。
隔离测试栈可显式放行精确的测试服务主机；此例外不作为生产默认值。
上游错误使用安全错误码，不返回可能包含密钥的诊断正文。
策略、解析、TLS、超时和连接失败各有有限错误分类；日志只记录分类，不记录认证头、URL、供应商正文或错误链。

## 不变量

1. 个人连接只能由其本人读取和修改，管理员角色不授予读取他人 Key 的权限。
2. 原始 Key 不进入 Cloud 服务、控制协议、Node、Thread、日志、截图或 Revision。
3. 一次运行的连接、模型及 Key 引用不因之后的配置编辑而改变。
4. 已撤销绑定不能被重新启用连接或更换 Key 复活。
5. 陈旧代次、未确认绑定、非模型用途证书及缺少模型代理能力的 Node 不能取得授权。
6. 模型请求不在 SQL 事务或数据库锁中执行。

## 为什么不是这些替代方案

| 方案 | 取舍 |
|---|---|
| 把个人长效 Key 注入沙盒 | 调用路径短，但 agent 和仓库脚本能读取 Key，平台不能撤销已被复制出的 Key |
| 所有人共享部署 Key | 少一个个人设置模块，但与用户要求的个人连接、权限和额度归属不符 |
| Cloud 转发模型请求并解密 Key | 少一个服务，但将业务控制与原始凭据/长连接合并，扩大控制面的敏感数据范围 |
| Node 自行读取所有个人配置 | 接线简单，但破坏只授权当前运行及冻结输入的约束 |
