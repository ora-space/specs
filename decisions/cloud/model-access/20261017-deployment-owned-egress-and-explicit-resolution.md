# 模型转发与 Cloud 资产下载共用部署方出网白名单和显式解析

model-gateway 模型转发与 Cloud 工作流资产 HTTPS 下载共用一份部署策略，企业模式只允许访问其中
列出的精确 HTTPS `host:port`；未列出的目标即使解析为公网地址也拒绝。
白名单内的私网地址仍须显式许可，cluster 网络、宿主地址、回环及链路本地始终拒绝。
两类目标域名由同一套部署方 resolver 或静态映射解析，不回退系统 DNS。
未启用企业模式的部署保持既有公网 HTTPS 与可信公网 DoH 行为。

`approved` 表示网络边界和启动加载、双服务重启生效的部署方式已有 owner 决策；本文规定其稳定契约，
不表示能力已经实现。
实现和部署证据齐备后才转 `implemented`。涉及 Cloud 保存门禁、model-gateway、Cloud 工作流资产
下载器与 cluster 部署装配；
不改个人 Key 入口、运行绑定、协议支持范围或数据库历史，不包含真实供应商能力与现场连通性验收。

## 问题与约束

公网地址分类不能表达部署方信任：企业网络可能使用登记为公网的地址，单独更换 DNS 会让用户把代理
指向任意公司服务。因此企业模式先检查目标身份，再检查全部地址，不能只给原公网策略加私网例外。
普通用户控制连接和凭据，部署方控制出口、解析信任和禁止到达的基础设施；两者不可互相授权。

## D1：同一份部署配置定义两类出网调用方的信任

首版配置使用包外 UTF-8 JSON `deployment-egress.json`，由部署管理员维护，只读挂载给 Cloud 和
model-gateway。Cloud 的模型连接保存门禁、工作流资产 HTTPS 下载器和 Gateway 模型转发读取同一
份配置、复用同一准入/解析语义；禁止分别维护模型/插件源白名单或让资产下载器写死 Cloudflare DoH。
`targets` 是共同的许可集合，没有按调用方区分的隐含默认项；列入资产源的 host:port 同样可以成为
模型连接的候选目标，反之亦然。部署方须按这个共同信任范围列项；网络许可不替代个人模型授权、
插件目录/来源校验或管理员安装权限，也不会将模型 Key 附加到资产 GET。
显式配置路径由服务启动参数提供，用户 API、连接记录、请求头和 agent 环境均不能覆盖它。
未配置路径保持原公网模式；一旦指定路径，缺文件、未知字段/版本、重复键、非法值或模式冲突均启动
失败，不能按“未配置”处理。`schemaVersion: 1`、`mode: public|enterprise` 显式区分两种策略。
生产同时设置开发 allow-hosts 与 enterprise 配置必须失败，不能让例外优先。

企业配置包含 `targets`、可选 `resolver`，以及必需的 `topology`。每个 target 是一个独立的
`host`、`port`、`allowPrivate`（默认 false）、可选 `allowedCidrs`、可选 `staticAddresses`。
同一 host 不同 port 是不同许可；重复目标拒绝。`allowedCidrs` 缺省表示没有额外 CIDR 限制，
显式提供时必须非空且每个地址都命中该目标的集合；不能合并其他目标的许可。无需每目标必填 CIDR。
`allowPrivate` 只打开 D3 所列私网类别，不解除绝对拒绝或其他保留地址限制。

以下仅为配置形状，保留域名/文档地址不是可运行的生产配置；无凭据、真实站点参数或连接 base path：

```json
{
  "schemaVersion": 1,
  "mode": "enterprise",
  "resolver": {"transport": "tcp", "address": "192.0.2.53:53"},
  "targets": [{
    "host": "model.example.invalid", "port": 443,
    "allowPrivate": true, "allowedCidrs": ["10.60.0.0/16"]
  }, {
    "host": "assets.example.invalid", "port": 443,
    "allowPrivate": true, "staticAddresses": ["10.61.0.10"]
  }],
  "topology": {
    "clusterCidrs": ["172.30.0.0/16"],
    "hostAddresses": ["192.0.2.10"]
  }
}
```

`public` 不接受 enterprise 专用字段，两类 HTTPS 出网统一使用既有部署 DoH 配置及公网数字
bootstrap；未配置时沿用原公网默认值，资产下载器不再独立选择 resolver。
首次启用需要支持本 schema 的服务版本；日常更换许可/DNS/个人 Key 不要求重建镜像，配置应用仍须遵守 D6。

## D2：按规范化后的精确 host 与有效端口匹配

需要出口准入的保存和每次模型转发都从服务端解析 `baseUrl`，仅接受 HTTPS 域名、无 userinfo/query/fragment 的
有效 URL。企业模式首版不接受数字 IP literal、通配符或后缀匹配；ASCII DNS 名按小写规范化，
允许一个末尾根点并移除后匹配，拒绝空标签、多个末尾点和未转换的 Unicode（国际域名须显式使用
ASCII A-label）。配置与 URL 使用同一规范化；省略端口等价于 443，显式端口须为 1–65535 的十进制数。
不通过字符串前缀、CNAME 名或反向解析获得许可。

`https://model.example.invalid/v1` 与同 host 的 `:443/other/v1` 命中同一项；`:8443`、
`model.example.invalid.attacker.invalid`、别名域名均不命中。路径继续由原协议规则追加接口，
不增加完整 base path 或协议白名单字段。host:port 许可意味着该站点的模型协议路径均在部署信任内；
站点若同时承载其他敏感服务，部署方应使用专用 host/端口，而非误以为有路径级隔离。

企业模式中未命中目标在 DNS 查询前拒绝，既包括通常的公网，也包括借用公网编号的内网（如 `7.x`）。
创建、重新启用连接及修改可调用连接时执行 URL、host:port、解析及 D3 门禁，解析失败不写入新连接版本。
网络 I/O 在数据库事务之外，提交仍检查身份、资源版本和幂等约束；已完成操作的合法幂等重放返回原结果，
不因之后的 DNS/策略变化重新执行准入。通过保存不等于之后可以拨号。Gateway 从冻结连接取得目标，
每次请求重新判定当前策略，不信任保存结果或客户端提供的已验证地址。

停用、删除连接和清除 Key 是降低权限的操作，必须在原有身份、归属、资源版本和幂等校验后完成永久
撤销，不依赖 host 是否仍在白名单、地址是否允许或 DNS/TLS 是否可用。服务停机期间按普通服务
不可用处理，不另设阻断撤销的出网开关。
PUT 保存 `enabled=false` 时，只有其他连接配置未变才属于纯停用；不能通过附带修改 URL/模型等字段
绕过普通配置校验。纯停用允许原样携带历史配置，不对它重跑新增的 URL/出口规则；调用方应先独立
停用，再另行修改配置。重新启用须重新准入，且永远不复活停用时已撤销的旧绑定。

## D3：检查全部地址，基础设施拒绝不能被允许项覆盖

所有 IPv4-mapped IPv6 先转为 IPv4，再按以下顺序逐地址判断。整个 A/AAAA 集合通过后才允许任选
其中的数字地址拨号；任何一个不允许、无有效答案或某一族查询失败均拒绝，不筛掉坏地址继续连接。
一族明确 NODATA、另一族成功可接受；超时/SERVFAIL 不算 NODATA。

| 顺序 | 判定 |
| --- | --- |
| 1 | 命中 cluster 任一 CIDR、宿主任一地址、回环或链路本地，始终拒绝 |
| 2 | unspecified、multicast、文档、benchmark/fake-IP、地址转换等既有保留/特殊地址仍拒绝；只对下一行私网类别提供例外 |
| 3 | RFC1918 IPv4 与 IPv6 ULA 要求该 target `allowPrivate: true`；否则拒绝 |
| 4 | 若 target 提供 `allowedCidrs`，该地址还须命中其中一项；不存在跨目标许可并集 |
| 5 | 其余满足既有公网地址规则的地址可通过，但企业模式仍以 D2 已命中 target 为前提 |

部署入口自动采集 Docker 网络（含默认桥接、Compose 网络和动态 Node/Workspace 网络池）的
IPv4/IPv6 IPAM 与宿主接口、网桥/网关地址，生成 `topology.clusterCidrs` 和 `hostAddresses`；
不能只读取 Gateway 容器自己的接口或所附网络。管理员可额外补充网段、宿主地址及 NAT/VIP 别名，
补充项与采集结果合并，不能删减已采集的拒绝项。部署命令对采集失败明确报错，不将其误报为成功。

自动采集结果是首版基础设施拒绝的数据来源，不要求管理员证明所有外部别名已经穷尽；没有额外
NAT/VIP 声明不阻止服务启动。应用不声称发现任意外部路由变化；网络池或宿主地址变化后由部署
入口重新采集，再按 D6 重启应用。企业 host 白名单是准入边界，拓扑拒绝是防止许可 host 解析到
基础设施的纵深防御；回环与链路本地仍由固定规则拒绝，不依赖拓扑文件。
许可与这些禁止项重叠时仍拒绝，包括“模型或 HTTPS 插件源正好在 cluster 网段”的情况。

## D4：显式 TCP DNS 或静态映射，不使用隐含解析路径

企业首版动态解析采用管理员指定的 DNS-over-TCP，`resolver.address` 必须为数字 IP 和端口，
直接连接该地址，不读取 `/etc/resolv.conf`、系统代理或搜索域，也不经 Docker 默认 DNS 发现 resolver。
TCP 是此 ADR 的细化选择：无需新增企业 DoH/CA 服务，但传输本身不提供 DNS 身份认证与保密；
部署方须提供可信、隔离的 resolver 通路。两类 HTTPS 出网均正常验证证书，DNS 被信任不等于目标
地址被允许。resolver 是独立控制流，只允许发送 DNS 查询，不作为业务 HTTP 目标；其可达性不授予
访问同地址其他端口的权限，cluster/宿主上的模型转发与资产 HTTPS 下载仍被 D3 拒绝。

只查询显式 host 的 A/AAAA。限制查询总时长、响应大小、记录数和 CNAME 深度，验证 DNS 响应的查询
关联；CNAME 的最终全部地址仍按原 target 校验，不能把别名加入白名单，也不从 authority/additional
区提取拨号目标。超时、截断/畸形响应、循环 CNAME、无答案或解析服务故障均拒绝，不切换系统 DNS、
公网 DoH 或另一套配置。具体限额在实现配置中固定并由直接测试证明有界。

target 的非空 `staticAddresses` 完全替代该 host 的动态查询，所有地址同样通过 D3；静态项失败
不再查 DNS。没有静态项的 target 必须有 resolver；全部 target 静态时可省略 resolver。
静态映射不改变 HTTP Host、TLS SNI 和证书 hostname 校验。静态映射与数字 resolver 均不使用系统
DNS 做 bootstrap。未启用 enterprise 的部署继续原有可信公网 HTTPS DNS，不使用此 TCP 通道。

## D5：当前策略约束每次转发和连接复用

Gateway 在每次请求（包括复用 HTTP/1 keep-alive 或 HTTP/2 连接）发送前检查当前 target 许可；
Cloud 资产下载器也在每次 HTTPS GET 发送前检查当前 target 许可。两者每次新拨号重新解析并检查
完整地址集合，只向已验证数字地址连接，不在实际 dial 时再按域名解析。
静态数据按进程启动时的快照生效。仅企业模式设置 30 分钟的最大连接存活时间；公网模式保持原行为，不设硬性存活上限，
避免企业扩展中断既有公网部署的长推理流。两种模式均按 60 秒空闲超时回收。模式范围和时长以直接测试验证；
企业连接达到存活上限后关闭，新拨号重新解析和检查全部地址，不无限复用。
不要求 DNS TTL 到期重验已建立连接，也不按策略版本维护多套池；同一进程只持有启动快照，策略
更新通过 D6 重启丢弃旧池。禁止跨 host 的 HTTP/2 合并。连接回收可能中断长请求，不自动重发模型生成。

TLS 始终验证原 URL hostname，禁用环境 HTTP/SOCKS 代理，不跟随 3xx；不能以 TLS 失败为由改用
HTTP 或跳过证书检查。用户提供的 host/模型/认证头不能覆盖冻结绑定。有限错误分类与诊断脱敏沿用
根决策；不把配置原文、现场地址、凭据或供应商诊断写入公开日志/统计。

## D6：改配置时停止全部出网服务、换文件、再启动

Cloud 与 model-gateway 只在进程启动时加载一次配置（含 topology、静态映射和解析策略），持有
各自不可变快照，不监听文件热更新；Repo Executor 加入后同样如此（D7）。指定的配置加载或校验失败，进程不启动，不回退公网或开发
模式。Cloud 保存门禁提供提前反馈，真正的出网拦截由 Gateway 转发前和 Cloud 资产取包前各自按
本进程快照执行；不依赖另一进程的请求级确认。两端短暂不一致可能导致保存通过而转发拒绝，或
保存被拒；它不免除实际出网方的独立准入校验，也不构成一次成功的配置更新。

配置更新通过部署入口按顺序执行：

1. 停止 Cloud、全部 model-gateway 与 Repo Executor，确认旧进程已经退出；停止终止在途模型流、资产下载并丢弃
   两端业务和 DNS 连接池，不自动重发模型生成。未完整取包/校验的任务不产生逐文档结果，之后只
   按既有资产触发规则重试。停止失败不得继续换文件或启动新服务。
2. 替换各服务共同挂载的 `deployment-egress.json`，包含自动采集与可选补充合并后的 topology。
3. 启动这些服务，各自加载并验证新配置。任一进程加载失败就不启动，部署命令报错，不静默恢复
   旧配置。需要回滚时由管理员显式选择旧配置并重复停服务、换文件、启动的流程。
4. 各服务通过 healthz 或管理接口报告规范化配置的内容摘要和 schema；`ora verify` 比较，缺失或
   不一致时明确报错，一致后才报告部署校验成功。摘要不包含原始配置、现场 URL 或凭据。

文件原地编辑不改变运行中的快照，必须重启上述全部服务；停机是终止旧流和旧池的边界，不另建激活
协议、服务间控制通道或调用开关。热切换、零停机与多副本栅栏留给后续。收紧策略后，仍有旧冻结绑定的运行也按
新许可拒绝；扩大许可不修改其冻结 URL/模型/Key。网络准入失败不等于数据库永久撤销，重新允许
目标可供尚未撤销且授权仍有效的绑定再次请求；已经永久撤销的绑定无论策略如何都不能复活。

## D7：共享网络准入，保留模型与资产各自的业务边界

| 调用方/路径 | 本策略覆盖范围 | 继承的业务约束 |
| --- | --- | --- |
| model-gateway 模型 POST、Cloud 连接保存门禁 | D1–D6 的共享白名单、解析、地址准入与启动快照；模型 baseUrl 仍拒绝 query | 冻结绑定、模型/认证头限制、Gateway 独占解密、永久撤销与不自动重发生成 |
| Cloud 工作流资产 `universal.url` 为 HTTPS 时的 GET | 同一配置与准入函数，逐次 GET/新拨号检查，禁止重定向与环境代理，按原 hostname 校验 TLS | 允许签名 query，仍拒绝 userinfo/fragment；保持原路径/query 字节语义，不用模型 URL 校验器拒绝签名下载；完整 URL/query 不写诊断 |
| Repo Executor 访问外部 Git 仓库（同步、发布、`probe`） | D1–D6 全部：同一份只读挂载的配置与准入实现，不另设仓库白名单；每个访问外部仓库的 `git` 子进程启动前重新解析并检查全部地址，以 `http.curloptResolve` 把检查过的数字地址交给 `git`，`probe` 用同一拨号器；不跟随重定向、不用环境代理；更换配置时与 Cloud、model-gateway 一起停止和重启，并参与 `ora verify` 的摘要比对 | 只用 Operation 指定的 Binding 与凭据，凭据只交给作用域内的请求；出网许可不授予仓库或凭据权限（[Repo Executor 根决策](../repo-executor/0-repo-executor-sole-external-git-boundary.md) D4、D9） |
| Cloud 工作流资产的 S3 object key | 沿用部署固定对象存储客户端、私有端点与已有认证；不属于目录指定远端 HTTPS 目标的通路 | object key 不能指定 host、URL、代理或自定义凭据，不能把被拒绝的 HTTPS URL 改走此路径 |

Cloud 在后台导入任务中实际取包时校验准入，不能只在目录同步/安装时检查。取包/地址策略拒绝、
解析故障、3xx、TLS 故障或切换取消仍是包级失败，不产生部分逐文档成功，不回退系统 DNS 或对象
存储；下一次管理员触发可按原规则重试。共同网络策略不意味着共同业务 HTTP client：资产下载仍有
连接 10 秒、响应头 30 秒、整包 60 秒及 16 MiB 流式上限，解压总量 64 MiB、条目 512、文档 256，
SHA-256 必须先于解包/解析。下载始终在数据库事务之外；逐文档语义、revision 围栏、成功幂等和
已导入副本不被卸载/升级改写的承诺保持原样。

内网 HTTPS 插件源必须在共享白名单中，且通过私网许可和基础设施排除；即使是随包提供的服务，
只要 HTTPS 地址属于 cluster/宿主/回环/link-local 也仍拒绝。部署内部对象存储须使用上述固定
object-key 通路，不能为本机 HTTPS 源开特例。本 ADR 不扩大到 Node 插件安装下载、市场 git 同步、
身份认证或任意 Cloud HTTP 调用；这些调用方若要纳入，须另行明确其身份与业务边界。

## 不变量

1. 企业模式的每次模型转发与 Cloud HTTPS 资产下载都先命中同一部署方精确 host:port 集合，任何公网分类都不能绕过它。
2. cluster、宿主、回环和链路本地拒绝优先于 target、CIDR 与静态映射。
3. 全部地址通过后才拨数字地址，TLS 身份始终是原 hostname；错误不触发隐含解析、代理或重定向。
4. Cloud 保存和 Gateway 转发使用相同策略语义，保存通过不能免除之后的地址和授权检查。
5. 策略更新以全部出网服务（Cloud、model-gateway、Repo Executor）退出后重启为边界，旧池和旧流已终止；配置加载失败不启动，不静默退回宽许可。
6. 部署策略不能改变个人凭据所有权、运行冻结或永久撤销结果。
7. 服务可用时，DNS 和出口拒绝不阻断已授权的停用、删除与清除 Key；降低权限不授予任何新调用权。
8. 两端各自执行本进程快照的出网校验，配置摘要不一致由 `ora verify` 报错，保存通过不能免除实际出网方校验。
9. 共享网络许可不携带个人模型凭据、不改变资产定位符与完整性边界，资产下载器没有独立白名单或 DNS 回退。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 只更换 DNS，继续允许所有公网 | 部署成本低，但借用公网编号的内部服务仍全部可达，无法表达站点信任 |
| 公网默认加白名单私网例外 | 公网兼容更宽，但同样挡不住未列出的借用公网编号地址；仅用于非企业的原规则 |
| 强制完整 baseUrl 与每目标 CIDR | 更细的约束有其价值，但增加路径/地址变更成本；本次批准粒度是 host:port，CIDR 可选 |
| system resolver 或失败后回退 | 运维方便，但引入未显式选择的解析与 fake-IP 路径，破坏解析信任边界 |
| 生产复用开发 allow-hosts | 接入快，但其例外能绕过生产地址规则，不能承担正式企业许可 |
| 热加载、激活协议或请求级对端确认 | 能提供更复杂的在线协调，但增加控制协议与故障状态；首版通过停止两个服务、换文件、重启及摘要校验完成更新 |
| TTL 到期重验旧连接、按策略版本维护连接池 | 增加连接复用状态和地址同步逻辑；首版只在新拨号检查全部地址，配合有界连接存活/空闲回收和重启生效 |
| 模型与插件源各自配置白名单/DNS | 可分开授权，但会产生两份部署事实及解析差异；本次选择共同集合，两类调用方仍各自校验业务授权 |

## 验收、落地与未解决范围

核心义务见[部署方共享出网用例](../../../test-cases/cloud/model-access/deployment-owned-egress.md)和
[工作流插件资产用例](../../../test-cases/cloud/plugin-marketplace/workflow-plugin-assets.md)。
先交付共享 schema/准入与 Cloud 保存、资产下载器、Gateway 转发接线，再交付 cluster 的自动拓扑采集、只读挂载、双服务重启及
`ora verify` 摘要比对，最后用受控双栈 DNS/TLS/连接回收和真实部署验证。完成定义包括非企业公网回归、保存/拨号
一致性、两类调用方的内网成功/白名单外借用公网地址拒绝、全部基础设施禁区、策略更新取消资产
下载/模型流、资产签名 query 与摘要/大小回归，以及旧绑定撤销；不能只凭配置
解析单测将本 ADR 改为 implemented。现有根决策保持 implemented，本 ADR 的新义务单独补证据。

实际 resolver、模型地址、CIDR、NAT 别名和真实模型能力由部署现场提供，不从名称推测。现场 Key
仍走个人凭据入口，不写入配置、镜像或公开仓库。动态热更新、多副本无中断栅栏、DoH/DoT 等额外
企业 DNS transport、企业 CA/IAM 和路径级许可留后续；这里不宣称已经验证任何真实企业模型。
