# Desktop 预备下一凭据，Gateway 以代次原子轮换并限时恢复回执

建议 Desktop 在发起轮换前将下一把随机凭据可靠保存到系统安全存储，Gateway 只保存 digest，
以会话代次和稳定续期 ID 原子替换当前资格。提交后旧资格立即失去业务权限，仅在固定
120 秒内用于恢复同一轮换回执；响应不返回新秘密，宿主用已经保存的下一凭据恢复。

本文为 `proposed`。协议形状、120 秒恢复窗口、24 小时建议轮换节奏和失败语义均待评审，
不是已发布 API 或已批准实现契约；批准后才维护核心用例。范围为可信 HTTPS 下的独立
Desktop 会话，不改变网页登录、provider OAuth、内部 JWT、部署签名身份与本地 Agent 凭据。

## 问题与约束

若 Gateway 生成下一凭据并只保存 digest，首次响应丢失后就无法原样重放秘密；若为恢复保存
可解密结果，则新增密钥托管、密文保留和恢复责任。宿主预备秘密可以消除服务端可恢复明文，
但要求客户端先可靠落盘，且必须解决双窗口、提交不确定、撤销与退出的竞争。

外部身份和 Cloud 授权继续由
[认证根决策](0-gateway-mediated-external-identity.md) 定义。本文的直接前序为
[部署绑定 Desktop 会话 ADR](https://github.com/ora-space/specs/blob/0eddd50e25ebb0e6408631b4653e4787f61e116c/decisions/cloud/identity-access/20261019-deployment-bound-desktop-sessions.md)，
其中 D5 要求有界轮换恢复，未选择秘密归属和具体状态机。固定提交链接指向同一份前序规则，
不把尚未落地协议描述为当前代码能力。

## 继承与修改

| 前序约定 | 本提案处理 |
| --- | --- |
| PostgreSQL 状态和服务端时间决定有效性；Cloud 授权始终权威 | 继承，不变；不把轮换成功当作资源权限或账号永久启用证明 |
| Desktop 默认空闲 30 天、部署可设绝对上限，恢复/续期本身不算活动 | 继承，不变；换代不重置会话创建时间或活动期限 |
| 宿主唯一续期所有者，恢复有限、旧资格不能无限普通访问 | 具体化为客户端预备下一秘密、单当前代次和固定回执窗口 |
| 凭据绑定部署签名身份与账号，TLS 和身份分别验证 | 继承；本协议先只用于可信 HTTPS，不暗中批准 HTTP 传输 |
| 在线撤销/停用检测至多 60 秒，本地功能独立 | 继承；失败停云端访问，不锁本地或误清秘密 |

## 决策提案

### D1：一个会话只有一个当前 bearer 资格

会话凭据形如 `d1.<session-id>.<secret>`，`secret` 为 CSPRNG 生成的 32 字节、无 padding
base64url 编码；`session-id` 是不透明 UUID，不是用户/部署可选身份。解析器严格限制格式和
长度，所有原生资格均从 `Authorization: Bearer` 进入，不能由 query、Cookie 或转发头替代。
Gateway 移除客户端提供的内部 header，仅向固定 Cloud upstream 签发短期内部凭据。

PG 会话权威记录包括当前 digest/代次、账号绑定、创建时间、最后活动/空闲期限、可选绝对
期限与撤销事实。秘密至少 256-bit 随机，digest 用 SHA-256；不能用口令替代，也不声称
digest-only 存储能保护弱秘密。宿主安全记录按部署签名身份与账号命名。

代次 `generation` 与活动序号为非负 64-bit 单调数，JSON 用十进制字符串，避免 JavaScript
整数精度丢失；溢出停止此会话并重登，不能回绕。新会话从代次 `0` 开始。

### D2：宿主先保存 Prepared，才允许发送轮换

宿主在唯一所有者下，从 `Current(g,T)` 生成续期 UUID `R` 和下一随机秘密 `N`，可靠写入
`Prepared(g,T,R,N)`，然后才发网络请求。写入失败不发送，保留旧 Current 与本地功能。
系统安全存储适配必须原子地保留整份记录，包括活动序号和上下文版本；换代提交不得用旧快照
覆盖已经推进的序号。不能先删除旧条目再分别写下一秘密和事务 ID。
不得把恢复材料写到明文日志、普通配置、遥测或同步数据。

| 宿主状态 | 事件 | 下一步 |
| --- | --- | --- |
| Current | 到建议轮换时点或收到明确需轮换结果 | 先可靠写 Prepared，再发同一 R 的请求 |
| Prepared | 收到成功且 generation 为 g+1 | 原子提交 Current(g+1,N)，随后删除旧 T/R |
| Prepared | 超时、网络/5xx、重启或响应丢失 | 保留完整 Prepared，走 D4，不生成另一 N/R |
| 任意 | 明确会话过期、撤销或账号停用 | 停云端资格，保留本地现场并提供重登；不靠轮换复活 |

建议 v1 `renewAfter` 是首次会话建立或上次轮换提交后 24 小时，由 Gateway 返回；宿主只在
在线且会话仍有效时执行，唤醒/联网先复核。该时点是轮换调度提示，不是新的 24 小时会话
绝对期限，也不承诺不合作客户端的旧 token 必在 24 小时后失效。空闲与绝对期限仍独立判定。

### D3：Gateway 在同一短事务提交新代次与有限回执

以下均是待评审的 Gateway 原生端点，不是 Cloud `/api/v1` 或现有浏览器 Cookie 路由。
部署路径前缀由已验证配置提供；不接受请求自行选择 upstream/部署身份。

| 方法与路径（前缀 /auth/desktop/v1） | 身份与输入 | 成功语义 |
| --- | --- | --- |
| POST /session/status | 当前 bearer，空 JSON 对象 | 返回当前 generation、serverTime、idleExpiresAt、可空 absoluteExpiresAt、effectiveExpiresAt、renewAfter、当前政策版本；不计活动 |
| POST /session/renew | 旧 bearer；requestId、expectedGeneration、nextSecret | 首次 CAS 或同一提交的有限回执恢复，返回非秘密代次/期限与 recoveryUntil；不回传 nextSecret |
| POST /session/activity | 当前 bearer；activitySequence | D6 的单调活动确认及当前期限；不轮换凭据 |
| POST /session/logout | bearer；可选 pending 轮换绑定与 nextSecret | D7 的终结操作，幂等 204；不新增会话 |

`nextSecret` 是下一凭据的随机秘密部分，不由客户端声明账号/权限。客户端本地可从既有
session-id 组合新 bearer。请求严格 JSON 解码、拒绝未知字段/重复键和额外值，正文限 4 KiB。
敏感请求体与 Authorization 不记录；响应 `Cache-Control: no-store`，不自动跨源重定向，
不为任意网页开放携带凭据的 CORS。浏览器 Cookie 不能调用这些原生端点。
renew 的上一代回执恢复及 logout 的 Prepared 双候选须在各自受限 handler 内校验，
不能先被“只接受当前 bearer”的通用中间件拒绝，也不能为了让它们通过而放宽业务 API。

Gateway 先在事务外获取当前 Cloud 账号启用结果；无法确认返回 503，不把旧的成功结果永久
缓存。随后锁定会话行，以锁内取得的 PG 当前时间 `now` 检查有效性，原子执行：

1. 当前 digest 匹配 `T`、代次等于 `g`，会话未终结且当前政策仍允许使用。
2. 下一 digest 与当前/上一 digest 不同；续期身份为 `(session-id,g,R)`，不能用于不同绑定。
   不承诺跨所有历史代次永久保存 R；旧代次已不能创建新轮换，故无需无界幂等墓碑。
3. 将当前资格变为 `N` 的 digest，代次变为 `g+1`，保存一份回执
   `(R,g,oldDigest,newDigest,committedAt,recoveryUntil)`。
4. `recoveryUntil = min(committedAt + 120 秒, effectiveExpiresAt)`，首次提交后固定；
   当前有效期限后来缩短时仍以更早期限限制恢复，不因政策扩展而延长原窗口。
5. 会话创建时间、最后活动、空闲与绝对期限均不因轮换改变；只更新建议轮换时点。

网络与 Cloud 查询不得放在 PG 行锁内。Cloud 停用与 Gateway 提交不是跨服务原子事务：
停用若刚好发生在查询后，资源请求仍由 Cloud 当前授权拒绝，并受已批准的在线 60 秒检测
约束收敛；不得将一次续期前检查描述为全局即时停用机制。

只有当前 digest 能调用业务 API、status/activity 或创建下一轮换。上一个 digest 仅在有效
窗口内、同一 `R/g/newDigest` 且当前仍为 `g+1` 时恢复原回执，不产生新代次或新秘密。
重放相同绑定返回同一 committedAt/recoveryUntil，状态期限字段按当前更严格政策返回；
不同 binding 的重复 R 或失败 CAS 返回 409，不把不同请求当幂等成功。

服务端至多保留一份立即前序回执；下一轮成功可淘汰它。清理不是失效判定，任何副本均须
在读取时检查窗口。未知或窗口外的旧 bearer 统一 401，不泄露历史资格是否存在。
已提交回执被后续代次取代时不能回放它来回滚资格。

### D4：不确定结果先试已保存的下一凭据

Prepared 恢复时先用 `N` 调 status，绝不重放业务副作用。

| 观察 | 宿主处理 |
| --- | --- |
| N status 成功，代次为 g+1 | 服务端已提交；可靠保存 Current(g+1,N)，再丢 T/R |
| N status 401，T status 成功且为 g | 服务端尚未换代；重发同 R/N 的轮换，不换 payload |
| 查询/轮换网络、503、未知状态 | 保留 Prepared，停止需确认的云端使用，退避后再复核；不自动开浏览器 |
| T status 401，原轮换在窗口内返回匹配成功回执 | 再验证 N；仅收到回执不自行合成第三把秘密 |
| 两把资格均明确无效，或冲突无法收敛到已知当前代次 | 停云端访问并要求重登，不无限尝试历史凭据 |
| N 成功但代次不符，或同 R 出现不同绑定 | 协议冲突；不盲写本地事实，保留诊断所需非秘密标识并重登 |

某次 status 失败与并发提交可能交错，不能仅根据一次 401 删除 Prepared；应在串行恢复中
重查两个候选并处理原续期结果。后台/5xx 不清凭据；只有明确失效或不可恢复冲突才进入
重登。系统安全存储再次写失败时保留 Prepared，N 已在其中，下一次恢复仍能验证它。

两个窗口必须共享同一宿主记录锁；跨进程使用 OS 互斥/安全存储版本检查，不能只依赖前端
内存 mutex。服务端 CAS 是最后防线：不同 R/N 并发只有一个赢家，败者不自动用旧 T 再开一轮。
下一轮换只能在 Current 可靠提交后开始，不维护多层 Prepared 链。

### D5：失效与错误优先，不将凭据轮换当设备证明

每次业务请求仍检查当前 digest、PG 会话状态/期限并使用 Cloud 当前授权；缓存内部 JWT
不允许绕过原生会话失效。恢复前必须验证部署身份和 TLS，切换目标取消未完成轮换上下文。
撤销/到期在 PG 锁下优先于轮换和回执恢复，撤销之后同一个 R 也不能重放成功结果。
提交前已受理的业务请求可以按原业务契约完成；提交后的新受理不得再接受旧资格，
不靠换代强制取消已接管任务，也不自动重传未知结果的业务操作。

| 结果 | 含义与客户端动作 |
| --- | --- |
| 400 invalid_request | 格式/长度/非法下一秘密；不变更会话，不当网络问题无限重试 |
| 401 unauthenticated | 未知、过期、撤销或不具此用途的 bearer；Prepared 按 D4 判断，不凭一次响应清全部现场 |
| 403 user_disabled | 经过当前账号判定的全局停用；停云端访问，不能与普通资源 403 混用 |
| 409 rotation_conflict | 当前已验证资格的代次/幂等绑定冲突；按 D4 收敛，不创建分支 |
| 429 / 503 | 有界退避；不清秘密、不算活动、不声称续期成功；尊重 Retry-After |

本方案是 bearer 资格，不是硬件绑定或防恶意客户端证明。盗取当前 T 的攻击者也能尝试
轮换；本协议解决诚实宿主的崩溃/并发和有限恢复，不证明谁是“真正设备”。旧资格误用不会
自动撤销整个会话，避免持旧秘密者无限把已恢复设备踢下线；管理性撤销仍是处置入口。
不声称本文等同 OAuth refresh token rotation 或满足所有 OAuth sender-constraining 要求。
[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700#section-4.14.2) 的轮换讨论用于威胁审视，
不是对自定义原生协议的合规认证。

### D6：活动独立去重，不以轮换或重试延长空闲

同一个会话保存最高已接受 `activitySequence`，跨凭据代次保留，不因换代清零。
宿主在安全存储中先推进序号，再发送汇总；允许空洞，不允许复用或回绕。
服务端对 `seq > highest` 且会话仍有效的请求，以锁内 PG 时间计一次活动；相等/更小序号
返回当前结果但不推进期限。有效到期为当前空闲期限与可选绝对期限的更早者。

普通客户端只汇总当前前台操作、编辑或查看/等待 Agent；后台、续期、状态探测与休眠不计。
离线、休眠或崩溃恢复后不补报积压活动，先 status，再等待新的前台活动生成更大序号。
Gateway 不信任客户端事件时间，也无法验证客户端是否伪造新序号：本规则仅限制正常客户端
与网络重试，不是人在场证明。过期会话即使收到更大序号也不能复活。

### D7：退出必须处理尚未确定的换代

宿主先停止新云端操作与轮换，保留协调器持有的 Current 或 Prepared 快照进行一次退出。
Prepared 退出携带旧 bearer 及 `(R,g,nextSecret)`；Gateway 在同一会话行锁下验证：

- 旧 T 仍当前时，撤销会话，使延迟到达的 renew 不能提交。
- N 已当前且代次为 g+1 时，凭 N 的证明撤销同一会话；不要求已过期回执仍存在，
  也不把 R 自身当作授权证明。
- 不匹配、未知、已终结统一幂等 204，不新增记录或返回历史秘密。

两个分支覆盖正常客户端的“退出请求在轮换前/后到达”竞争；不把未知 bearer 的 204
解释成对任意其他已泄露资格的设备管理证明。退出响应丢失/断网时清本机资格并说明远端
撤销未确认，不留完整凭据作后台撤销队列。页面/其他设备会话和已启动远端任务保持独立。

## 不变量

1. 任何对外轮换请求前，下一资格和事务绑定已经可靠保存；落盘失败不发送。
2. 一次 CAS 至多建立一个新当前代次；当前资格只保留 digest，回执不含可重放明文秘密。
3. 旧资格从提交开始失去业务访问，只在固定且不续延的窗口恢复同一回执。
4. status、renew、logout、回执和网络重试都不等同用户活动。
5. 到期、撤销、当前政策与 Cloud 授权不能被轮换结果覆盖。
6. 任意不确定状态保留本地现场；恢复不能自动发送消息、创建任务或上传草稿。

## 为什么不是这些替代方案

| 方案 | 优点与代价 |
| --- | --- |
| 服务端生成 N 并加密保存回放结果 | 集中生成秘密，但增密钥托管/备份/清理责任；仅存 digest 无法恢复原秘密 |
| access/refresh 双资格 | 可分离用途与短期暴露，但仍需 refresh 的丢响应恢复；本次先保留单资格边界 |
| 旧 T 普通访问宽限 | 客户端简单，但窗口内两个资格可访问，扩大泄露与并发状态 |
| 失败就清凭据重登 | 状态少，但网络或短暂服务故障反复打断使用并丢失恢复事实 |
| 无限保留回执或旧资格 | 提高任意长离线恢复率，但破坏有限恢复/撤销边界并积累秘密责任 |

## 风险、兼容与评审后落地

系统安全存储必须能保存 Current/Prepared 的原子记录，这是三平台适配的验收前提。
随机秘密生成、digest 比较、严格解码、限流及多副本并发均需直接证据，不能由顺序单测代替。
单资格轮换不提供防盗设备绑定；恶意/被攻破客户端风险仍靠失效、停用和部署绝对上限控制。

新增 Gateway 表/约束采用向前迁移，不改已应用 SQL；旧浏览器 Resolve/TTL/退出语义不变。
本文不选择发现/挑战的签名编码、首次登录交接的完整字段、三平台密钥库产品或 HTTP 例外，
不声称整套原生认证协议已经齐备。上线阶段还必须评审这些接缝和最低实际发布版本。

owner 选择方案与窗口/节奏后，先纠偏本文并转 approved，再依据最终状态机补核心用例；
实现须覆盖提交前/后丢响应、安全存储落盘失败/重启、双窗口/副本竞争、撤销/到期交错、
活动乱序/重放和退出竞争。产品实现通过后再按最终行为更新 implemented。
