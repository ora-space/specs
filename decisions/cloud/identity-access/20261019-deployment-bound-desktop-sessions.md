# Gateway 以部署签名身份交接独立 Desktop 会话，会话策略归部署方

Gateway 向 Desktop 暴露可验证的部署身份与版本/能力，经系统浏览器交接独立原生会话；
默认连续 30 天无有效活动过期、不设绝对上限，允许部署方缩短期限或设置绝对上限。
Cloud 继续拥有当前用户与资源授权，Desktop 不取得 provider secret、provider token 或内部服务密钥。

本 ADR 为 `approved`，尚未实现。它继承本领域前序
[独立 Git Credential Store](20261016-git-credentials-in-independent-credential-store.md)，
只扩展 Gateway 的原生客户端身份与会话边界；Desktop 交互和状态所有权由
[宿主连接根 ADR](../../desktop/cloud-connection/0-host-owned-cloud-connection-and-session.md) 承担。
新增会话不改写已存在的浏览器会话及 provider 政策，不把当前网页 Cookie 或内部 JWT 延长使用。

## 继承与修改

| 前序约定 | 本 ADR 处理 |
| --- | --- |
| [认证根决策](0-gateway-mediated-external-identity.md)：Gateway 外部认证，Cloud 授权，PG 为会话权威 | 继承；Desktop 会话同样不能绕过当前用户/资源授权 |
| 根决策 D5–D6：浏览器绝对 TTL、非空 expires_at、30/90 天上限、Resolve 不续期 | 浏览器不变；新增独立 Desktop 会话策略，不给旧行取消上限或改变读取语义 |
| 根决策 D1：生产 public origin 与 provider callback 为 HTTPS | 保持默认；内网 HTTP 仅能在显式部署支持下作为例外，须有独立配置/能力与风险交互，不能自动启用 development 或削弱其他部署 |
| 根决策：外部身份归一、稳定 source/subject、短期内部 service/user JWT | 继承；新增 Desktop 会话不能扩展内部 JWT 生命周期或签名用途 |
| [华为身份关联](20260923-huawei-global-id-alias.md)、[Git 提交身份](20260928-user-git-commit-identity.md)、前序 Git Credential Store | 继承；Desktop 登录不隐式合并身份、不修改提交身份、不授予外部仓库访问 |

## 决策

### D1：发现与能力协商先于认证

Gateway 公布部署 ID、公钥、版本、交接/回调方式、身份挑战、会话策略与续期协议能力。
探测与身份挑战不要求已有会话；能力声明只说明协议支持，不代表账号权限。
Desktop 按已验证目标的协商结果行动，缺必需能力即说明升级方向，保持本地可用，不回退为
网页 Cookie 导出、长期内部 JWT 或不安全的旧协议。

URL 与认证入口由部署显式配置，保留路径前缀；请求参数、Host 或转发头不能选择 Cloud upstream。
新增 API、字段、错误和配置必须在实现时同步正式契约及验证，不把本文语义表当现有路由。

### D2：稳定签名身份独立于地址和 TLS

部署持有稳定 deployment ID 与签名密钥，随部署数据备份与迁移；部署身份密钥与内部 service/user
JWT 签名用途分开。Gateway 对新鲜随机 nonce、deployment ID、协议上下文签名，响应有受验证的
时效。Desktop 校验记录的公钥、完整签名载荷与本次 nonce，重放、仅声明相同 ID、同 ID 换密钥
均不能证明旧身份。

首次 TOFU 由用户记录公钥指纹，可经管理员线下指纹核对。持有同一签名私钥即处于同一身份信任域，
不能把恢复出来的副本声称为不同部署；密钥泄露不能用换 URL 修复。迁移保留身份后仍需会话数据
与策略连续，丢失会话权威数据时要求重登，不靠身份证明重建有效会话。

TLS 验证先于挑战；身份签名不能豁免证书异常。HTTP 的签名挑战不保护会话机密，也不防透明转发。
地址变更仅在身份、传输信任与能力均通过后沿用仍有效会话。不同 ID 或公钥按新 server 登录。
带凭据请求不自动跨源跟随重定向，重定向不作迁移授权。自动密钥轮换和旧 server 签名迁移声明
不在首版范围。

### D3：浏览器批准的事务最多产生一个 Desktop 会话

Desktop 是无 provider secret 的原生客户端。Gateway 复用部署现有 GitHub OAuth 与可用网页会话，
明确显示目标部署、账号与切换入口。外部 provider callback 仍回 Gateway，不直接回 Desktop；
Gateway 到 Desktop 的交接是另一个绑定事务，不能混用 provider code 或 provider PKCE。

| 交接事实 | 必须绑定/满足 |
| --- | --- |
| 登录事务 | deployment ID、公钥身份、目标地址、随机 state、PKCE S256、回调目标和有效期 |
| 一次性交接码 | 默认 2 分钟，服务端公布期限；绑定上述事务及已验证账号，不包含长期凭据 |
| 换票 | 原事务已验证 server，核对 state、PKCE、身份、回调目标，原子消费并至多建立一个 Desktop 会话 |
| 回调 | 协商过的 loopback 或 deep link；Gateway 限定回调种类/目标，不能成为任意地址重定向器 |

未登录页面不能凭任意调用者提交的账号 ID 签发会话，网页批准受既有同源/CSRF 保护。
外部身份验证不在数据库锁内执行，消费交接码与创建 Desktop 会话在同一权威事务中完成。
未知、过期、重放、并发重复、跨部署或绑定不符的换票均拒绝；失败不能回退发送完整会话到 URL。
换票响应丢失不能再创建第二个会话；无可安全恢复的结果时重新开始登录，不把新事务当旧事务重试。
凭据只存在于宿主系统安全存储与必需的传输内存，PG 保存不可逆验证材料；Cloud 不接收原生会话秘密。

### D4：Desktop 会话的期限与活动由部署方策略控制

Gateway 公布空闲期限、绝对上限是否存在、当前到期时间、活动上报节奏、续期方式与恢复边界。
默认空闲期限为 30 天，无绝对上限；部署方可缩短期限或设置绝对上限。设置绝对上限时到期必须
重登，不能被活动、重试、轮换或客户端时钟延长。原生会话与网页会话、其他设备会话独立计算。

PG 当前状态与服务端权威时间判断有效性。有效活动可推进空闲期限，已过期、撤销或停用的会话
不能复活。活动汇总的迟到、重放、乱序不得重复推进或越过绝对期限，客户端时间不能授权延寿。
普通请求、后台存活探测与续期本身不等同于用户活动。

前台操作、编辑、前台查看/等待 Agent 属于正常客户端活动；无人查看的后台任务、心跳、续期
与休眠不属于。只汇总活动，不采集键鼠内容。Gateway 无法核实上报真伪：空闲过期只防正常
客户端长期无人使用，不能防恶意客户端伪造活动。真正的安全边界仍为撤销、停用、部署方绝对上限。
验收只要求正常客户端遵守活动规则，不能要求服务端识别伪造上报。

新策略不能只改客户端倒计时：策略版本/权威期限必须在服务端校验与协商中一致。缩短策略后，
恢复与续期按当前策略重判，不承诺保留旧期限；扩展策略不能复活已终结会话。

### D5：轮换恢复有界，故障不变成清凭据

宿主统一协调续期。轮换协议在创建替代资格前确定稳定的逻辑续期身份与当前会话代次，
服务端必须幂等处理同一续期并对并发轮换做代次隔离；相同逻辑续期不同绑定不能被接受。
宿主在请求前把恢复所需状态保存到系统安全存储，只有确认替代资格可恢复后才丢弃旧状态。

协议必须公布有限恢复期限、旧资格仅可用于哪次恢复、何时完全失效；不能把旧凭据作为
无限期业务凭据，也不能让重复恢复不断重置窗口。恢复结果仍须经过到期、撤销与停用校验。
服务端已提交但响应丢失、宿主收到新资格但尚未持久化、两个窗口并发和崩溃重启，都必须能
收敛到一个当前代次，或明确要求重登；不能留下两个永久活跃分支。

本 ADR 固定这些恢复义务，不选定尚未评审的票据格式、恢复窗口数值或密钥托管机制。
第一阶段实施前必须在后续协议 ADR 明确完整状态机、恢复秘密归属、原子提交顺序、有限窗口与
失败矩阵；它是交付门禁，不是允许实现无限接受旧凭据的空白。
网络、超时和 5xx 保留本机资格与现场，不反复打开浏览器；只有明确无效才停止会话使用。

### D6：逐请求授权与有界失效检测共同成立

Gateway 每次受保护请求校验当前 Desktop 会话，仍只向固定 Cloud upstream 签发短期内部凭据。
Cloud 当前用户停用、membership 和资源授权保持权威。资源 `403` 不等于账号停用，需可区分的
会话/账号状态结果；原生状态探测不能靠一个可选业务资源的 `403` 推断全局账号状态。

在线且有云端连接时，撤销/停用检测至多 60 秒；长连接在撤销时关闭，或在同一界限内复核。
后台复核不计活动。即使缓存内部 JWT 尚有效，也不能绕过原生会话失效检测。
启动、唤醒、恢复联网后先复核再恢复云端访问；已知到期即停用。离线无远端事实，只显示离线
缓存；无法按时复核时不继续云端使用，临时故障不误清本机凭据。

退出仅撤销当前 Desktop 会话；同账号其他设备及网页会话独立。按身份管理性撤销必须覆盖
该身份的相关原生会话，不因拆分存储而漏掉；不新增面向用户的设备管理界面。
离线退出只确认本机清理，远端撤销未确认必须如实提示，不为事后撤销保留完整访问凭据。
撤销、停用与退出不主动取消此前已启动的服务端任务，任务依原生命周期和当前授权处理。

### D7：分阶段交付，安全前提从第一阶段成立

| 阶段 | 范围与前置 | 完成条件 |
| --- | --- | --- |
| 1 | 可信 HTTPS、稳定签名身份/TOFU、能力协商、loopback、独立 Desktop 会话、策略/活动/续期/撤销、单账号隔离；先批准轮换恢复协议 | 三平台正式包完成登录/恢复/退出，故障/重放/撤销/崩溃矩阵有直接证据；D1 本地独立始终成立 |
| 2 | 增加 deep link，继承阶段 1 的身份、state/PKCE、账号隔离与唯一事务所有权 | 三平台包注册/多实例/开发正式隔离及跨方式攻击验证；发起前协商，不任意切换 |
| 3 | 自签/私有 CA 指纹交互、显式内网 HTTP、同身份地址迁移 | 证书变化、浏览器信任、身份不同/同 ID 换密钥/重定向/旧址不可达均有证据，本地独立仍成立 |

阶段 3 的 HTTP 不是把现有生产 HTTPS 检查删除：部署需显式启用受支持的原生 HTTP 入口，
公开地址、浏览器认证/Cookie 及 provider callback 的兼容契约须在实现前另经协议评审。
保留可信 HTTPS/受信浏览器入口的能力；不承诺 provider 接受任意 HTTP callback，也不承诺
HTTP 加签即可等价 HTTPS。没有这些前提时报告登录能力不兼容，不假装完成 HTTP 登录。

新增持久状态经向前迁移，不改已应用 SQL 或把旧浏览器 session 自动转型。旧客户端/旧 Gateway
没有能力时保留原有行为，新客户端说明升级方向；最低版本按实际发布确定。
各阶段未实现的能力保持不可用并明确提示，不能借分期省略身份/回调绑定或撤销边界。

## 不变量

1. Gateway 验证认证，Cloud 判定当前授权；原生登录不授予额外资源权限。
2. 有效凭据只属于一个部署签名身份与账号，URL 变化不能改写归属。
3. 一次交接最多创建一个会话，长期秘密不进入回调 URL、日志或 Cloud。
4. PG 权威时间、状态与部署政策决定期限，过期/撤销/停用不能被续期复活。
5. 恢复窗口有限且不能通过重试延长；并发轮换不产生永久凭据分支。
6. 浏览器、各 Desktop 设备的活动与退出彼此独立，管理性撤销不遗漏新增会话类型。
7. Cloud 或认证不可用不改变本地文件、Agent、编辑与运行资格。

## 为什么不是这些替代方案

| 方案 | 优点与未采用原因 |
| --- | --- |
| 将网页 session 改为滑动无上限 | 表结构少，但改变所有部署既有网页政策与数据库约束 |
| 将内部 JWT 延长为 Desktop token | 减少会话查找，但破坏内部短期凭据、撤销与签名用途边界 |
| 用客户端活动证明人在场 | 省去绝对上限，但 Gateway 无法验证恶意上报，不能作为安全保证 |
| 无限接受上一个 token | 减少丢响应重登，但把有限恢复变成永久双凭据和撤销绕过 |
| 一套任意 HTTP development 开关解决自建 | 实现少，但会连带放松 dev provider、Cookie 与浏览器边界 |

## 风险、后续边界与核心用例

TOFU 依赖首次核验；部署签名私钥与会话权威数据需要一致备份，密钥泄露处置不在首版自动轮换内。
无绝对上限部署接受会话泄露窗口的代价，撤销与停用能力必须可验收。
三平台回调、安全存储、休眠恢复与证书交互不能只以协议单测代替正式包验证。

后续协议 ADR 必须补齐 D5 恢复状态机及 D7 HTTP 浏览器/部署契约；接口字段、签名编码与能力版本
由协议评审固定，未评审内容不得标作已实现。组织统一配置、自动密钥轮换、签名迁移声明、
设备管理、同步、隐式上传与外部 Git/模型授权不在本文范围。

[原生会话核心用例](../../../test-cases/cloud/identity-access/desktop-sessions.md) 的直接证据均为
`Missing`。既有浏览器会话测试继续约束浏览器行为，不能代替 Desktop 活动、恢复或失效证据。
