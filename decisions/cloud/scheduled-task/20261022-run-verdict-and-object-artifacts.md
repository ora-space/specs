# Cloud 定时运行由服务端从 Thread 提取 verdict，产物经受限上传独立保存 30 天

本提案让 Cloud 的定时运行以 IssueRun 为身份保存独立业务结论，并把声明的文件上传到 Cloud 管理的私有对象存储。
verdict 由 Cloud 读取已接管的 Thread 记录推导，用户与 Agent 不直接写数据库；产物在运行 Workspace 释放前由 Node
采集，经 Cloud 校验后登记。建议产物从接纳时起保留 30 天，费用归部署运营方，不向个人模型连接扣费。

本文处于 `proposed`，上述保留期限、费用与上传方案均待 owner 批准，不构成现行实现契约。
涉及 Cloud、Controller、Node 的定时运行结果接缝；不扩展手动 IssueRun、WorkflowRun、交互式 Thread 的结果协议，
不实现 local 上传或同步，不替换 IssueRun 状态机。核心测试用例在批准后依据最终决策维护。

## 决策

### D1：verdict 归属 IssueRun，只有成功运行公开业务结论

Cloud 为带定时触发来源的 agent IssueRun 保存可空的 `verdict`、`verdict_detail`、`verdict_at`，以及解析来源
`execution_id / turn_id / terminal_sequence`。字段归属运行而非 occurrence，任务历史裁剪后仍能从 issue 的运行详情读取。
来源绑定在接纳时持久保留；不以 occurrence 当前是否仍存在判断运行是否为定时触发。

枚举固定为 `pass / warn / fail / blocked / idle / range_unresolved`，不接受 `custom`。
运行状态与结论不互推，`completed` 在任务历史投影为 `succeeded`，可以同时有 `verdict = fail`。

| 执行事实 | 公开 verdict |
| --- | --- |
| IssueRun `completed`，有有效最终轮哨兵 | 解析值与可选 detail |
| IssueRun `completed`，无哨兵或解析非法 | `null`，显示「未报告」 |
| 非终态、`failed`、`cancelled`，含截止取消映射的 `failed · timeout` | `null` |
| `missed`、接纳失败或跳过，无 IssueRun | `null` |

`verdict_at` 是 Cloud 提交注解的数据库时间，不更新运行排序时间，不改写 `failure_reason`、终态、Timeline 成败或重试策略。
旧运行不回填推测值。原始 Thread 中出现的标记始终作为用户内容保留，不因此成为公开 verdict。

### D2：Cloud 在成功终态事务单次写入，Thread 只提供持久证据

Cloud 在 IssueRun 即将提交 `completed` 的同一数据库事务内，读取属于该运行已登记会话执行、初始用户轮次的持久 Thread
记录。仅在该轮有成功 `TurnEnded`、记录连续且完整时，重建该轮最后一条 Assistant 消息的文本块；排除用户消息、思考、
工具参数与工具结果。存在 `Gap` 或无法重建时按未报告处理，不从更早消息、别的轮次或别的执行借用结论。
会话结束前所有记录须已持久接管，沿用 Thread 事件序号与终态的顺序约束。

哨兵解析复用 local D2 的语义：LF 归一，标记与枚举大小写不敏感，行尾空白忽略、不跨行，取第一个有效
`QA_VERDICT: <枚举>`；代码 fence 中的文本也参与；detail 只认紧随的一行 `QA_DETAIL: ...`，上限 2000 个 Unicode
标量值。非法输入整体记未报告，不写一半注解。该约定只由用户写进随 revision 冻结的 Prompt，服务端不注入隐藏指令。

唯一写入者是 Cloud 运行结算用例，不暴露公开写 verdict 的 API，也不把 Node 的结构化 verdict 声明当权威。
注解与运行终态一起提交或回滚；相同结算重放返回既有值，不再次解析、更换来源或更新时间。数据库失败必须回滚，
不能吞错后确认成功。解析失败只影响注解，不把合法 Thread 事件变成无法 ACK 的毒消息。

这样增加 Cloud 对会话内容的有限解释，代价是需跟随 `ora-history` 格式维护读取器；收益是无需新增 Agent 工具、
外部写接口或第二套事件传输。普通交互式 Thread 仍按原契约保存与展示。

### D3：Node 在交付阶段采集，产物失败独立结算且不延长运行窗口

只对初始轮成功结束、未请求取消的定时运行采集。Node 在现有 Revision 交付执行中、运行 Workspace 释放之前扫描
checkout 根下 `.ora-scheduled-artifacts/`，仅接受 `markdown / json / txt / log / xml / html`；目录约定由用户 Prompt
提供。固定目录之外不收集，不把会话 JSONL、环境变量、模型配置或部署凭据自动加入产物。

单文件 ≤ 10 MiB，单运行 ≤ 64 个，合计 ≤ 64 MiB；拒绝项清单也限制为 64 条，并附超出条数汇总，防止海量文件名
放大数据库与响应。文件名按 UTF-8 字节序排序后确定收集集合，超限项有稳定原因。只收普通文件，拒绝绝对路径、`..`、
盘符、ADS、符号链接、junction 与硬链接；用目录句柄约束读取范围，检测扫描到上传期间的替换或大小变化。
名称只作展示元数据，不能参与对象键、路由或本地目标路径拼接。

首次扫描将清单身份、源文件摘要与大小持久化到 Node 的交付账本；同一交付执行重放使用原清单，不重新扫描得到不同内容。
交付重试产生新工作项与新尝试身份，不覆盖前次上传。Cloud 为运行选择至多一个已验证清单，后续尝试不得改写已发布结果。
无目录或空目录为 `empty`，无需创建虚假对象。

产物采集、上传与核验使用既有交付尝试的截止窗口，不续期、不新增运行阶段。产物失败可记录为 `failed` 或
`partial`，不阻止代码与 JSONL 的既有交付结算，不把 Revision 成功改为失败。到达既有放弃窗口时，未完成产物登记明确
结算为失败；释放前已登记的结果不依赖 Node 存活。IssueRun 最终失败或取消时不发布产物，已上传对象转入清理。
未配置对象存储、未派发交付、启动失败或失败收尾均显示 `not_collected` 及稳定原因，不表示「有零个成功产物」。

### D4：Cloud 先持久化上传计划，再授权并独立校验

增加专用的产物上传计划与登记接缝，受现有 Controller lease epoch、执行、租户、运行 Workspace、generation、Node
和交付阶段绑定约束。Node 通过 Controller 提交清单，Cloud 在数据库事务中验证上限并分配不可变的产物 ID 与对象键：
`scheduled-artifacts/<tenantId>/<runId>/<deliveryWorkId>/<artifactId>`。上传计划先于对象写入提交，保留预留字节数、
大小、SHA-256、有效期与状态。Controller 不持对象存储凭据，不把文件内容塞入控制流。

Cloud 只为计划内固定键签发短期单键 PUT，绑定摘要、大小与 `If-None-Match: *`；授权不写账本、数据库、事件或日志。
授权过期可重签，执行身份过期则拒绝；不允许续签令已取消或已释放执行复活。412 不代表同内容，仍须校验。
v1 内部协议新增字段/方法并做兼容性检查，不改变既有 `GrantRevisionUpload` 的键集合与行为。

Node 报告上传完成后，Cloud 事务外逐对象核验存在、长度与 SHA-256；随后在短事务中重查身份、epoch、运行状态、
未过期且未进入删除的计划，再幂等登记验证结果。对象查询不持数据库锁。相同身份不同清单/摘要拒绝，旧 epoch 不可登记。
只有已验证且所属运行最终 `completed` 的对象成为可读取产物；上传成功但 SQL 回滚可按原计划重放，不能凭 Node 声明发布。

计划逾期、运行失败、取消、未选中的重试对象进入 `deleting`。清理者先在事务中将计划封闭并撤销新授权资格，
待最后签发的 PUT 授权过期并经过对象入口强制的最大上传请求时限后再删对象；URL 到期只阻止新请求，不能证明已开始的
PUT 结束，因此部署入口必须限制单次上传的总时长。登记事务拒绝 `deleting`，避免 HEAD 后清理与登记竞争。
删除调用在事务外，404 视为成功，失败重试；删除责任与墓碑保留至确认，服务重启后继续。
对象存储部署必须禁止公开读取与绕过 Cloud 的写入，并限制预签名请求大小；桶外人工删除只能显示对象缺失，不伪造保存成功。

### D5：读取跟随当前 issue 权限，REST 是唯一结果来源

任务历史与 IssueRun 详情从同一运行结果投影 verdict、产物汇总和采集状态。按 `run_id` 列举产物元数据：
稳定 ID、展示名称、类型、字节数、登记时间、过期时间与可用状态；被拒项提供安全名称和原因，不返回宿主路径或底层错误。
不返回桶名、对象键、对象存储凭据或永久 URL。旧运行的结果能力显示 `not_collected`，不能与空清单混同。

Cloud 提供独立的经鉴权下载接口，校验当前有效租户成员资格及绑定 issue 的读取权限；不存在、跨租户与无权限统一 404。
过期产物对已授权读者显示 `expired`，下载返回 410；对象意外缺失显示 `unavailable`。不发可在撤权后继续使用的下载签名 URL，
Cloud 代理流式读取，下载前重查权限。内容以附件提供，安全编码文件名、`nosniff`；HTML/XML 不在应用同源内执行或内联展示。
Agent 内容是不可信用户内容，类型白名单不等于内容扫描，不承诺发现其中的密钥。

结果变更提交后发布只含 issue/run 标识的失效提示；SSE 不带正文、verdict detail、产物内容或下载能力。
任务历史和运行详情都重新读取 REST；漏事件与重连不会丢失事实。结果在运行终态后才发布，通知仍沿用既有成败规则。

### D6：建议独立保留 30 天，由部署承担存储费用

每个运行的产物到期时间固定为运行接纳时间加 30 天，使用数据库时间，重试、下载与注解不续期。
100 条 occurrence 裁剪、禁用或软删除任务均不提前删除产物，也不删除 verdict；通过 issue 仍可读运行结果。
issue 或租户失去访问资格时立即禁止下载；物理删除仍由到期清理承担，不能因用户不可见而丢失清理责任。
到期先在数据库标记不可读、封闭上传与登记，再异步删除对象。元数据保留最小过期/失败事实，区别从未采集与曾存在后过期。

这明确不同于 local「每任务 10 个运行、随历史裁剪」策略。30 天使无人再运行、停用任务也有有界对象生命周期，
代价是旧 IssueRun 保留审计事实但不保证文件永久可下载。verdict 作为小型运行注解跟随既有 IssueRun 审计保留，
本文不为 Thread、Revision JSONL 或 Git refs 另加回收规则。

存储、请求与下载流量由 Cloud 部署运营方承担，不消耗任务创建者的模型额度、不向离开的创建者追记模型账单；
元数据保留接纳时的创建者与租户归属以供用量统计。首版不引入收费价格表、余额扣款或转移付费人。
部署须显式启用产物功能并设置有限的租户字节配额；配额数值由部署决定，未配置则不开上传。
签发前按租户在事务中预留总字节数，已登记、未完成与待删除对象均计入，直到实际删除确认才释放；并发申请不能越额。
配额不足只拒绝产物并展示原因，不改变调度接纳、执行结果或模型费用；不得用静默提前淘汰绕过 30 天承诺。

## 不变量

1. Cloud 只从属于本运行的持久 Thread 证据推导 verdict，业务失败不改变执行层结果。
2. 注解与成功终态原子提交，同一运行单次注解，任务历史裁剪不丢注解。
3. Node 无法选择对象键，上传能力绑定当前执行与已提交计划，旧 epoch 不能写入业务登记。
4. 可下载产物已经过 Cloud 的存在、大小和摘要校验，且运行终态为 `completed`。
5. 文件传输、HEAD 和 DELETE 不在数据库事务或锁内执行。
6. 产物失败不会延长运行与交付窗口，不改变代码交付或物理回收证据。
7. 结果读取服从当前租户与 issue 权限，原始凭据、对象键与短期授权不进入公开结果。
8. 清理不以历史条数、任务启停或创建者是否在场为触发条件；字节配额直到确认删除才释放。
9. local 文件与 verdict 仍只在本机，不因本 ADR 自动上传。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| Agent/前端直接提交 verdict | 结构化且简单，但新增写权限与可伪造来源；持久 Thread 已有可核验输入 |
| Node 解析并单独报告 verdict | 靠近 history 格式，但重复跨进程接管与来源绑定；Cloud 仍需校验其与 Thread 一致 |
| verdict 在成功 TurnEnded 时立即公开 | 更早显示，但后续运行失败/取消会与只允许成功运行的矩阵冲突 |
| 产物嵌入会话 JSONL 或控制事件 | 少建上传链路，但破坏 Thread 单条边界，增加重放负担且无法独立下载和清理 |
| 文件留在沙盒或只提交到 Git | 减少存储组件，但释放即丢文件或把报告永久混入代码与 Git ref 生命周期 |
| 随 100 条历史或任务软删除清理 | 实现简单，但与根 D6 的视图裁剪边界冲突，issue 运行详情会因任务维护而丢内容 |
| 对象永久保存 | 审计方便，但费用与无人运行任务的空间无界；建议保留最小元数据、文件到期 |
| 向个人模型连接收存储费 | 看起来统一，但模型凭据没有对象存储结算能力，混淆两类费用归属 |

## 风险、未解决的问题与落地

owner 需确认的产品取舍是 30 天固定保留、部署运营方付费并显式配置租户配额，以及 Cloud 对 Thread 业务内容的有限解释。
也可选择短保留期限降低成本，或先只交付 verdict、产物后续再做；代价分别是报告可追溯窗口变短或不能保存报告。
本文不决定收费价格、内容扫描、业务 verdict 告警/自动重试、人工改写结论、跨设备同步、全局并发额度。

旧运行与旧协议不回填、不伪装采集成功。新能力上线需 Cloud/Controller/Node 同步具备专用上传协议；未具备时不启用产物，
继续执行既有运行并明确返回 `not_collected`。不能把普通 Revision PUT 权限扩大来兼容旧 Node。

落地按以下阶段推进，批准之前只维护提案：

1. 批准后建立本领域核心用例，覆盖矩阵、终态事务、证据来源、权限、对象不可变、配额、清理与崩溃窗口，初始证据 `Missing`。
2. Cloud 先交付 verdict 存储、Thread 读取、结算与公开投影；验证重复终态、失败/取消、裁剪后的读取和提交后失效提示。
3. 三端交付计划/上传/核验与配额、重试清理，覆盖真实 PostgreSQL 和对象存储；上线前验证旧 epoch、过期授权、HEAD 后竞态。
4. 接入 Web 历史与下载，真实运行只生成产物，验证沙盒释放后可下载、撤权拒绝、30 天过期及删除重试；确认代码交付与产物失败互不改写。
5. 按直接证据更新用例和 ADR 状态。不得以本提案存在代替 Scheduled Task 根决策 D8 的真实栈验收或解除 Desktop 禁用门禁。
