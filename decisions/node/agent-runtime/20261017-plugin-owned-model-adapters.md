# 插件 adapter 拥有 CLI 模型配置，Node 拥有运行授权和资源生命周期

Node 为一次会话提供固定版本的模型访问上下文，插件 adapter 将它转换为自己所驱动 CLI 的配置与
协议；Node 保持授权领取/续期/撤销、目录和进程生命周期的所有权。新接入兼容协议的 Agent 不再
要求 Cloud 页面或 Node 授权模块增加插件 ID 分支。新的模型协议仍需平台实现，不由插件声明授权。

本决策为 `approved`，尚无新 adapter 路线的实现证据。首期交付 Claude 普通会话、OpenCode 回归和
测试插件的扩展证明；不实现 Pi RPC/SDK 桥接、Codex Responses、其他 CLI 或多 CLI 工作流。
不重写现有 ACP 运行时，也不声称修复根决策记录的孤儿后代/guardian 缺口。

## D1：模型访问上下文是一次启动的受控输入

在既有 Agent 启动契约上提供版本化扩展，而非建立第二套调度/会话协议。逻辑上区分以下信息：

| 输入 | 来源与用途 |
| --- | --- |
| 执行身份与冻结发行 | Cloud 已登记的会话、Plugin ID、包版本/target/摘要、声明指纹和 adapter 契约版本 |
| 冻结非秘密配置 | 本次配置 revision、已验证 Settings、模型协议、明确模型 ID 与元数据 |
| 运行时访问材料 | Node 凭专用身份取得的固定平台代理地址、短期令牌、公开 CA 信任材料及生命周期状态 |

第一、二组可通过受控控制输入传递；第三组只在本次会话的敏感运行通路存在。真实上游 Key 和
model-access 客户端私钥永远不提供给插件。上游地址不是 plugin 自行转发的目标，adapter 得到的
是平台代理地址；不能用 Settings 覆盖它或重新选择绑定。

具体 IDL 字段与生成类型属于产品协议的实现，但必须有明确版本、能力检查和失败分类。旧
`agent/start` 只有 cwd/hostVersion 的形态不构成已支持新能力。没有新上下文的历史执行保持原语义；
要求个人模型的新版插件不能把缺上下文当作允许使用本地默认值。

## D2：准备、握手与第一条 prompt 有严格顺序

1. Node 核对执行指定的安装包及声明关联，取得安装使用租约，准备本次执行的私有工作负载目录。
2. 核对宿主/插件声明的 adapter 契约与协议能力，用专用证书为指定 binding/execution 领取临时授权。
3. 通过既有插件启动与宿主管理的子进程通路，交付本次模型访问上下文；adapter 生成 CLI 配置并完成
   必要 provider 初始化。CLI/ACP 的实际就绪和绑定应用成功之后才允许首条 prompt。
4. 任一阶段失败明确终止准备，若已领取授权则撤销并停止续期；关闭已启动的进程并清理本次临时资源。

声明匹配并不证明 adapter 真的应用了配置。握手结果、固定 adapter 的行为测试及网关的每次模型/
授权校验分别承担不同义务；不能仅相信插件返回 ready。身份/声明/契约不匹配必须在首次模型调用前
拒绝，不能启动另一个版本、直连上游或用部署 Key 重试。

上下文的非秘密冻结身份、Settings 和版本属于 D1 的可持久控制输入，须与执行账本记录一致，以供
重试校验和审计；这不允许在重试时重新读取个人默认值。第三组中的临时令牌、私钥内容及带认证头的
provider 初始化材料不能进入控制账本、JSONL、用户 prompt、普通 Settings、错误链或用户日志。
公开 CA 和固定代理地址不是秘密，但也不据此把整个 provider payload 原样记录。沿用平台有限安全
错误类别区分配置不完整、不兼容、授权拒绝和准备失败；原始供应商/CLI 错误不直接公开。

## D3：CLI 差异在 adapter 内，授权和进程责任留在宿主

adapter 拥有协议名映射、CLI 参数/配置文件序列化、字段优先级、provider 初始化、模型别名以及
CLI 事件到既有 ACP 会话语义的转换。它通过已有 host-managed spawn 获得子进程，不用另一套后台
进程或临时脚本绕过宿主管理。Cloud 和通用授权模块不根据插件 ID 生成各 CLI 原生文件。

允许 adapter 内复用固定版本 ACP providers 或 CLI/SDK 的配置接口，但它们是插件内部依赖，不是
Cloud 数据库或个人 settings 的公共结构。静态声明不包含任意模板程序；用户字符串按字面数据校验
和序列化，不能借配置变成 shell 表达式、任意环境展开或原生 CLI 配置覆盖。

宿主仍拥有启动/取消/结束的责任、工作负载身份、安装租约、公开 CA 发布与临时目录。声明和用户
选项不能修改平台执行/文件/网络策略。CLI 的权限模式、敏感文件规则、hooks 或内部插件不是个人
模型授权；其存在也不证明操作系统沙盒或权限限制有效。

## D4：每个冻结绑定独立隔离，禁止共享 provider 切换

一个会话执行使用自己的插件生命周期、CLI 连接和私有状态，不在多个用户/绑定之间共享可变
provider 状态。即使两个执行有相同 cwd，也不能通过同一进程的 providers/set 来回切换个人连接。
普通用户配置编辑不通知在途 adapter 热切换；在途会话只能使用创建时的冻结输入。

CLI 的 HOME、配置/缓存/会话目录和生成的非秘密配置位于 checkout 外；长期 Key 不进入沙盒，临时
令牌仅在内存或本执行的环境中，配置文件只引用受控临时变量，不写令牌明文。公开 CA 可供工作负载
读取，Node 客户端私钥保持管理身份私有。不得读取宿主登录文件或从继承环境取得原生 provider Key。

仅换 HOME 不足以证明路由固定。adapter 必须处理该 CLI 的专用配置目录变量、项目设置、环境和
其他高优先级设置，确保它们不能将本次授权路由改向另一个上游、模型或登录态。保留用户项目文件；
不能覆盖或删除仓库设置来假装隔离。不支持可靠覆盖控制的固定版本拒绝进入此能力，而不是容忍
不确定路由。模型代理仍按当前绑定验证每次请求，插件声明不替代该验证。

## D5：模型发现和别名不能扩大冻结输入

网页配置先使用个人连接中的模型目录，不依赖启动一个无凭据的 Agent。确需 adapter 发现模型时，
它必须处于已授权的执行上下文；额外发现不能制造未经准入的影子运行或读取别人的配置。缓存身份
至少区分执行/用户隔离范围、Plugin ID/发行、声明/配置 revision 和模型绑定，不能只有 cwd。

Claude 首期使用一个 Messages 连接和一个明确模型。adapter 将主/辅助别名映射为该模型，实际
请求 ID 与冻结值一致；会话配置选项不能扩大允许集合。无法验证辅助调用、别名或运行中选择不会
越界时不开放该版本。可选模型发现/计数接口按平台支持矩阵处理，不能为 CLI 默认探测开放任意代理。

Pi 的 RPC/SDK、Codex 的 Responses、其他 CLI 的双模型配置均是后续 adapter/协议工作；不能因
字段名或 fork 来源类似就宣布兼容。新增兼容插件应只需包、声明与 adapter 及其测试；新增模型
协议仍需要平台明示支持和验证。

## D6：授权撤销、结束与清理保持同一个会话所有者

Node 在到期前续期同一令牌，续期任务随会话结束停止。一般授权拒绝取消对话并失败关闭；已验证
身份的 `model_session_ending` 仍按上一份 ADR 有界等待持久结束命令，保留用户结束原因。
取消/失败路径不得重新打开 provider 或重新从当前个人设置取授权。

正常结束停止新调用和续期、撤销授权、终止并回收所管理的进程，再释放租约和清理本次临时状态。
准备失败、进程退出、Node 正常停止也必须收敛到同一责任链；不得清理其他执行或用户 checkout。
Node 重启按既有 interrupted 规则处理，不能从旧临时配置恢复令牌。未纳管孤儿后代的既有缺口需单独
证据，不从“正常退出成功”扩大成全栈崩溃恢复已完成。

## 兼容与落地

先扩展版本化上下文、共享生成类型和准备门禁，再把 OpenCode 的专属转换迁入插件 adapter，随后
交付 Claude。旧 OpenCode 数据/默认选择的兼容过渡只能留在明确的旧路线，不能成为新插件缺能力
时的回退。发布新包与宿主支持顺序需匹配，新包不能只因安装成功就被标为模型可执行。

Node 协议/Cloud 执行输入仅新增必要的冻结非秘密配置，原协议字段身份、JSONL 和历史运行保持原义。
不是本期需要的 transport、动态权限或共享状态不借扩展点一起增加。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| Node 为每个 CLI 增加分支 | 易集中调试，但 Node 发布被 CLI 格式变化牵动，插件扩展不成立 |
| 万能 env/file 模板引擎 | 静态映射简单，但优先级、provider 交互和事件转换会逼成另一门语言 |
| Cloud 直接持久化 ACP providers 参数 | 省一层转换，但外部 unstable 字段和临时头会污染业务契约 |
| 共享 adapter 进程、按请求切 provider | 节省进程，但配置是连接级时会串用用户授权 |
| 直接下发上游 Key | 路径短，但无法撤销已复制的长效 Key，破坏既有凭据边界 |

## 不变量与验收

1. Node 不获取真实上游 Key；插件不能选择另一个绑定或读取管理私钥。
2. 首条 prompt 之前，包、声明、能力、配置与授权必须一致且已应用。
3. 每个冻结绑定的可变 provider 状态和临时资源独立；普通编辑不热切换。
4. adapter 拥有 CLI 差异，宿主拥有生命周期与策略；不产生新调度器。
5. 模型发现、别名和可见会话选项不能扩大授权集合。
