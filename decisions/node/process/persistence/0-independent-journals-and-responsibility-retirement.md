# 宿主与 Guardian 独立持久化，按责任退休并保留旧请求拒绝依据

宿主独立保存管理意图，各 guardian 独立保存运行事实，以幂等协议汇合。关键元数据采用 SQLite
WAL 与 `synchronous=FULL`，提交成功后才确认持久接受。Scope 在收尾、结果责任与资源关联均
处理后退休，详细历史可回收，拒绝旧请求的依据继续保留。

本根决策为 `proposed`，不冻结 schema 和物理路径；现有文件不得被新布局覆盖。迁移与版本回滚
由[升级决策](../upgrade/0-version-coexistence-and-safe-migration.md)约束，不能以重建数据库抹除恢复责任。

## 背景与约束

宿主和 guardian 独立存续，不能依赖跨进程共享内存或跨库原子事务。无限保留全部输出与历史不可行，
但按时间删除去重记录可能让旧请求再次执行。结果接管和退休需要独立于普通日志轮转。

## 决策

### D1：每份持久事实只有一个写入权威

| 存储 | 写入者 | 原子保存的责任 |
|---|---|---|
| 宿主 SQLite | 宿主 | 请求去重＋意图＋协调责任；状态＋变更发布责任；结果接管进度 |
| Scope SQLite | 对应 guardian | Run 身份＋参数＋启动阶段；观察事实＋待报告记录＋序号 |
| 输出分段文件 | 对应 guardian | 输出政策承诺的数据及可读范围 |

正常运行不直接写对方数据库，不使用跨库事务。事实通过可重传、可去重协议汇合；恢复工具取得
独占恢复资格后才能处理原存储。Guardian 失效后的新收尾事实不能伪造原始退出结果。

### D2：确认服从实际耐久边界

关键元数据使用 WAL＋`synchronous=FULL`，批量提交可以合并写入，但提交前不得确认。
WAL 的本地文件系统与 checkpoint 要求、FULL 的提交同步语义见
[SQLite WAL](https://www.sqlite.org/wal.html) 和
[SQLite synchronous](https://www.sqlite.org/pragma.html#pragma_synchronous)。实际耐久性仍须故障测试。
选择包含已知 WAL 修复的引擎版本，并检查实际链接版本，不能只查看声明依赖。

输出不逐字节写入元数据事务。承诺持久的输出先持久化数据，再提交“已持久可读”偏移；恢复处理
未提交尾部。可丢弃日志可采用不同刷盘政策，但不能误报可靠保留。输入接受的耐久级别与
[交付未知](../io/0-bounded-output-and-fenced-input.md)同时落实。

### D3：退休以完成责任为前提

```text
关闭并封闭新运行入口 → 按实际保证收尾 → 处理结果责任与资源解除关联
  → Scope 退休 → 回收详情，保留拒绝旧请求所需依据
```

| 数据 | 回收条件 |
|---|---|
| 可淘汰输出／诊断日志 | 符合政策，读取者可识别缺口 |
| 未接管完成记录 | 指定方已接管，或显式承担放弃责任 |
| Guardian 事实 | 宿主已接收必要事实、收尾完成、恢复不再依赖 |
| Scope 详情 | 运行收尾、结果责任和资源关联均处理 |
| 去重／退休依据 | 能证明旧请求再到达仍只会被拒绝 |

未知或已退休 scope 的 Run 请求不得隐式创建 scope。ScopeId 永不复用；详情回收后保留精简
退休依据。进一步压缩须有能拒绝整个旧身份范围的协议，不能仅靠 TTL。

### D4：存储失败保留责任

磁盘不足、权限错误、记录损坏和关键写入失败必须可观察；不能自动确认结果、伪造完成或释放资源。
无法可靠接受新操作时暂停接受属于故障处理，不引入运行数量准入或配额模块。恢复后应可继续协调。

## 不变量

1. 持久接受确认不早于相关事务提交，两个数据库正常运行时各有唯一写入者。
2. 持久可读偏移不超前于已持久输出；交付未知不被去重记录缺失掩盖。
3. 退休和详情回收不使旧身份重新有效，存储故障不解除未完成责任。

## 为什么不是这些替代方案

| 方案 | 取舍 |
|---|---|
| 宿主与 guardian 共写一个数据库 | 查询方便，但耦合存续与写入权威，扩大锁与故障影响 |
| 提交前回复、后台刷盘 | 延迟更低，但崩溃后无法解释已确认接受的责任 |
| 所有记录统一 TTL | 回收简单，但迟到请求可绕过去重或丢失未接管结果 |

## 落地与验收

先实现关键接受与事实汇合，再补输出提交与结果接管，最后实现退休和压缩。
覆盖提交／回复间强杀、输出未提交尾部、事实确认丢失、磁盘满、权限错误、记录损坏、退休后旧请求
及结果确认丢失；同时证明记录保留和条件恢复后的继续推进。

## 本决策未解决的问题

SQLite schema、事务边界、汇合确认、输入去重耐久范围、checkpoint 和保留默认值需冻结。
Scope 退休与 Node 资源解除关联的确认协议、旧身份范围拒绝与压缩机制仍需设计；本 ADR 不指定
未经验证的数据库版本或路径布局。
