# Git 与插件共用进程入口，Node 以清理和业务对账交接资源

Git 和插件通过注入的 Adapter 使用 process-client；Node 持久关联 Execution、资源、Scope 和 Run，
由业务领域解释结果和重试。资源占用在 scope 关闭、达到所选清理保证并完成必要业务对账后释放。

本根决策为 `proposed`，适用于新体系业务接入，允许重构现有 Git／插件接口。
运行层接受不透明 scope 身份，不解释仓库冲突；Worktree 业务规则仍归
[Node Worktree](../../worktree/0-worktree-management.md)。本决策不自动迁移旧运行或取消外部服务任务。

## 背景与约束

当前 `crates/gitlancer/src/exec/runner.rs` 直接启动 Git，插件子进程使用 `ora-process`。
如果只更换 reaper 而保留旁路，Git 副作用不能获得统一恢复保证。另一方面，进程租约失效或
直接进程退出不证明共享仓库可重新写入，运行层也没有足够领域知识判断资源冲突。

## 决策

### D1：Client 暴露远程句柄和真实阶段

| 句柄 | 责任 |
|---|---|
| `ProcessSession` | 持授权连接宿主，创建／接管 scope，封装续租与连接恢复 |
| `ProcessScope` | 有效控制权下启动 Run、观察和显式关闭 |
| `ProcessRun` | 观察事实、I/O、终止和等待收尾 |

Client 隐藏 endpoint、握手、续租、原身份重传、快照订阅衔接及平台错误归类；暴露实际保证、
接受状态、启动未知、输出完整性、控制权失效和清理结果，不压成退出码。启动接受与实际启动、
关闭接受与关闭完成分别可观察；只读观察资格不等于变更资格。

Drop 只释放本地句柄，取消等待只取消等待，终止运行需显式操作；整个 session 不再续租后按
租约规则处置。Git 可封装启动、等待和捕获结果，插件使用持续 I/O，两者共享相同底层模型。

### D2：业务主进程和直接辅助命令统一入口

Node 在启动前持久记录业务关联；每条 Git 命令独立分配并保存 RunId，多步骤操作的 Adapter
不能在通信重试时生成新身份。Git 解释仓库事实与结果，插件解释会话、命令确认和是否重启，
运行层解释启动、I/O 与清理。RunId 与上层 ExecutionId 不混用。

目标业务主进程和直接启动的辅助命令均走新入口，后代由所选纳管实现覆盖。Node 引导宿主、
宿主引导 guardian 属独立基础设施启动协议，不可被业务作为旁路。测试可注入 fake，生产不设
隐式无纳管后端。按调用方迁移，同一尝试只走一套体系，不双跑有副作用命令；旧运行明确停止交接。

### D3：资源占用与 Scope 关联持久化

Node 侧独立模块拥有冲突判断与资源关联，运行宿主不解释仓库或 worktree。

```text
持久记录占用及关联 scope → 启动访问资源的运行 → 使用结束或异常恢复
  → 关闭 scope 并按实际保证收尾 → 业务对账／外部副作用协调
  → 持久释放资源 → 放行冲突工作
```

强模式要求静止证据；尽力模式允许完成尽力清理与业务对账后按政策自动恢复，同时保留无法证明
全部后代退出的事实与残留风险。部署或运行政策可一次性选择，无须每次异常交互确认；已知冲突
进程存活或清理失败时两种模式均不能伪装完成。

### D4：冲突边界不等于路径或单 Run

租约失效、直接进程退出、数据库锁释放均不自动释放资源。开放 scope 还可启动新 Run，单 Run
完成不释放 scope 共同占用；提前释放独立部分需划分独立 scope，或另行设计具有同等证据的协议。

不同 worktree 可共享仓库元数据，Git 领域定义资源身份与冲突集合。一个协调域只有一个有效
资源分配权威；未来多个 Node 访问同一共享存储时，权威必须覆盖全部参与者，不能各自分配互斥使用权。
本地进程静止不等于 Git hooks 或插件外部任务结束，业务对账保留这层责任。

## 不变量

1. 同一命令尝试只有一个持久 RunId 和一个实际执行入口，通信恢复不产生新业务尝试。
2. 资源放行有清理与业务对账依据，控制权失效和单 Run 完成不替代 Scope 关闭。
3. Git／插件规则由其领域拥有，进程层不重建冲突政策或解释业务协议。

## 为什么不是这些替代方案

| 方案 | 取舍 |
|---|---|
| Git 继续直接 spawn，仅插件接入 | 改动少，但 Git 仍有未纳管副作用和恢复旁路 |
| 用 worktree 路径作互斥身份 | 容易计算，但遗漏多个 worktree 共享的仓库元数据 |
| 租约失效自动释放占用 | 恢复快，但旧进程或外部服务可能仍在写入 |
| Client Drop 隐式关闭 scope | 本地 RAII 简洁，但临时句柄释放会意外终止远程运行 |

## 落地与验收

先在控制权切片实现资源持久关联与恢复门禁，再迁移 Git 和插件真实入口。验证 Git 已改变文件
但结果未保存、Node 强杀后立即重启、多个 worktree 冲突、插件接管后的命令对账和外部任务仍运行。
Fake 证明调用语义，跨独立进程、持久存储及真实 Git／测试插件证明业务恢复。

## 本决策未解决的问题

Git 仓库／worktree 冲突集合、hooks 与辅助程序纳管前提、插件保留运行的会话恢复协议及资源
解除关联确认需在各领域冻结。跨 Node 共享存储协调仅明确权威约束，不在本版新建机器级管理器。
