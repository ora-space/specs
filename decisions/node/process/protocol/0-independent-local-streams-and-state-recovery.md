# 本地通信使用三条独立流，以快照、变更流和结果接管恢复状态

Node—宿主与宿主—guardian 各自使用绑定同一认证会话的 Control、Events、I/O 独立字节流，
采用长度前缀与 MessagePack。查询使用权威快照与可续订变更流，完成记录另按持久接管确认保留。

本根决策为 `proposed`，只约束新进程体系的本地协议，不更改
[Controller–Node Protocol](../../protocol/0-controller-node-protocol.md) 的传输与编码决策。
两个协议边界分别握手和版本协商；不兼容版本的退出与迁移由升级决策负责。

## 背景与约束

控制权续租不能排在无限输出之后；一次读取不保证得到完整消息。事件历史需要有界，但事件轮转
不能删除尚无人接管的结果。宿主查询投影也可能落后于 guardian 的原始事实。

## 决策

### D1：三条流隔离流量，绑定同一身份

Linux／macOS 使用 Unix Domain Socket，Windows 使用 Named Pipe。每对通信方建立三条独立流：

| 通道 | 内容 | 恢复 |
|---|---|---|
| Control | 授权、续租、启动、查询、撤权、停止及回复 | 租约窗口内恢复，到期执行策略 |
| Events | 状态变化与结果通知 | 游标续订或快照重同步 |
| I/O | 原始输入输出与流控制 | 输出按政策续读，输入核实原交付状态 |

所有通道验证同一会话，不能仅凭自报 ScopeId／RunId 接入；Events／I/O 活动不代替控制权续租。
跨通道没有天然全局顺序，消息通过请求身份、Run、代次及事实版本关联。队列和任务分离，控制锁
不能等待 I/O；具体交付承诺见 [I/O 决策](../io/0-bounded-output-and-fenced-input.md)。

### D2：共享编码结构，不混合业务消息

长度前缀明确 framing，MessagePack 表达结构化消息与二进制负载；规定最大帧、输出分块和
大查询分页。参见 [MessagePack specification](https://github.com/msgpack/msgpack/blob/master/spec.md)。
编码格式本身不证明语义兼容。Node—宿主、宿主—guardian 分别定义业务消息、握手和版本，
仅共享传输结构及必要类型，不建立全局消息集合。

### D3：快照与订阅无缝衔接

快照提供状态、版本、事实新鲜度及核实情况；宿主投影落后不构成再次启动的依据。变更流使用
游标与有限重放，从快照对应游标订阅；历史不足显式返回需要重新同步，日常恢复不要求完整历史。
状态更新与对应变更发布责任在同一事务保存，避免状态已提交但通知责任永久丢失。

### D4：结果接管独立于事件轮转

完成记录在指定接管方持久接管前保留。Node 持久保存结果及后续责任后确认；确认丢失可重传，
不能触发第二次业务处理。诊断观察者不自动成为结果接管者，其离线不永久阻塞回收。
详情删除条件由[持久化决策](../persistence/0-independent-journals-and-responsibility-retirement.md)负责。

## 不变量

1. 三通道均绑定有效认证会话，只有 Control 续租维持控制资格。
2. 快照到订阅不静默漏变化，历史缺失显式要求重同步。
3. 未接管完成记录不被普通事件轮转删除，重复确认不重复业务处理。

## 为什么不是这些替代方案

| 方案 | 取舍 |
|---|---|
| 单字节流承载控制和全部输出 | 连接少，但需要额外证明拥塞下控制不被阻塞；本地边界选择物理隔离 |
| 无限事件回放作为恢复基础 | 模型直观，但历史增长无界且恢复成本持续增加 |
| 查询快照即确认结果 | 少一步协议，但读取不代表后续责任已持久接管 |

## 落地与验收

先冻结身份、版本及握手，再接入三流与快照／订阅衔接，最后验证接管与回收。
覆盖拆帧、粘帧、超限、独立断线、输出拥塞、跨流乱序、快照并发订阅、游标回收和确认丢失。

## 本决策未解决的问题

两套 wire schema、语义版本兼容规则、请求冲突判据、事实版本和游标范围、帧与分页大小、会话
通道绑定细节尚需冻结。不能从另一层 Controller–Node 的消息编码推导本协议实现。
