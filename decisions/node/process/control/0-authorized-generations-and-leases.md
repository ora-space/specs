# 以可验证授权、持久代次和租约落实 Scope 控制权

Controller 授权具体 Node 实例，宿主持久验证授权顺序，并逐 scope 将控制权撤销落实到 guardian。
连接断开保留租约恢复窗口；租约到期后旧代次永久失效。撤权完成与旧运行收尾完成分别报告。

本根决策为 `proposed`，细化[架构边界](../architecture/0-node-host-and-scope-guardians.md)。
它约束新体系全部变更和输入通道，不迁移旧 reaper 的 PID 登记，也不以授权成功证明资源可复用。

## 背景与约束

旧 Node 暂停后可能在新实例接管时恢复。仅断开连接或在宿主内存中替换 owner，不能阻止
guardian 执行旧队列。必须区分实例授权、scope 控制权和实际写入结束。

## 决策

### D1：身份各自承担独立语义

| 身份 | 用途 |
|---|---|
| 稳定 `NodeId` | 逻辑 Node 归属 |
| Node 实例身份与授权代次 | 被授权实例及其新旧顺序 |
| 宿主实例身份 | 宿主本次运行、连接恢复与旧凭据失效 |
| `ScopeId` 与 Scope 控制权代次 | 不可复用的运行组及其当前变更权限 |
| `RunId` | 请求前确定并持久保存的一次启动尝试 |
| 请求身份、事实版本、事件游标、I/O 序号 | 分别处理请求幂等、事实顺序、订阅和字节交付 |

这些身份不能用 PID、路径或物理连接替代。字段名和 wire 编码尚未冻结；共享领域定义见
[术语表](../../../../domain/glossary.md#node-process)。

### D2：授权顺序持久化，不能由 Node 自报

Controller 持久分配单调递增的 Node 实例代次，授权绑定实例身份并可验证；Cloud 部署的权威
保存边界遵循 [Controller–Node Protocol](../../protocol/0-controller-node-protocol.md)。
宿主保留接受过的最高代次，同授权重投幂等，同代次绑定不同实例则拒绝。Controller 重启和程序
回滚均不能倒退授权事实。旧 Node 不能通过自报更大的数字取得权限。

已授权 Node 向本机宿主续租，Controller 暂时不可用不打断其工作；创建替代实例或改变授权归属
需要授权方参与。实例授权成功后仍需逐 scope 交接，相关 guardian 未落实撤权时不得报告完成。

### D3：实际执行时检查租约和代次

连接断开仅进入恢复窗口。租约到期永久撤销旧代次，迟到续租不得复活；每个变更实际执行时检查
资格，不能仅靠后台过期任务。经过授权的接管可以提前撤权。

撤权与启动、终止、stdin 实际写入必须存在明确先后关系：撤权前接受的运行纳入原 scope 处置；
撤权后旧请求拒绝；旧代次下排队但未交付的输入不能在撤权完成后继续写入。已交付字节无法撤回，
后续影响按[业务会话规则](../io/0-bounded-output-and-fenced-input.md)恢复。

### D4：失权政策与时钟明确

Scope 创建时选择终止或保留策略。终止策略关闭 scope，恢复执行需新 scope；保留策略允许原运行
继续，新控制者仍需恢复业务会话。当前 Git 使用终止策略。失权不直接释放资源。

运行期间以单调时钟判断期限；跨宿主重启、休眠和系统重启的恢复算法必须先定义，不能复用旧进程
计时值、复活旧权限或无依据延长停止期限。日志及面向人的时间使用本地时间。

## 不变量

1. 同一 scope 在任一时刻只有一个有效变更权威，所有变更与输入通道遵守同一授权。
2. 过期或撤销的代次不因迟到消息、重连或回滚恢复有效。
3. 撤权完成意味着 guardian 已阻止旧权限继续产生新的交付，不意味着先前副作用已结束。

## 为什么不是这些替代方案

| 方案 | 取舍 |
|---|---|
| 断线立即终止 | 故障反应快，但短暂 transport 故障也摧毁可恢复运行 |
| 只在宿主入口验权 | 校验集中，但旧 guardian 队列可在交接后继续写入 |
| Node 自增代次或每次续租依赖 Controller | 前者可越权，后者把临时控制面故障扩大为本地运行故障 |

## 落地与验收

先冻结凭据与代次持久化，再实现 guardian 执行点验权，最后接入租约及资源交接。用显式同步点
复现旧 Node 暂停、新实例接管、旧实例恢复及迟到输入；同时验证短暂断线可恢复，期限到达后不能复活。

## 本决策未解决的问题

凭据签发、验证、存储、轮换、通道绑定及同 OS 用户下插件与管理凭据的信任范围尚需冻结。
宿主更替、授权刷新与 guardian 持久代次的交接顺序，以及跨重启期限算法和默认租约时长需单独证明；
这些缺口不允许弱化旧权限永久失效的承诺。
