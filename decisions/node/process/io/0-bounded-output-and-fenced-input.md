# Guardian 持有双向 I/O，输出有界，输入按控制权交付

Guardian 持有 OS 管道并在宿主重启期间持续处理输出；Node 通过可重连接口读写。输出按用途
选择有界政策，输入保序、按身份去重并显式暴露交付未知。进程控制权恢复与插件业务会话恢复分别呈现。

本根决策为 `proposed`，基于[控制权](../control/0-authorized-generations-and-leases.md)及
[生命周期](../lifecycle/0-durable-run-attempts-and-scope-closure.md)。它不承诺无限离线无损输出或
stdin 业务命令恰好一次处理，不迁移旧体系管道；传输与数据提交分别见协议和持久化决策。

## 背景与约束

有限存储、无限输出和消费者无限离线不能同时满足无损且永不阻塞。另一方面，字节写入 OS 管道
与持久记录不具备原子性；重复 stdin 命令可能再次产生业务副作用。

## 决策

### D1：按通道用途选择输出政策

| 用途 | 默认政策 | 达到限制后 |
|---|---|---|
| Git 等结果捕获 | 有界保存并报告完整性 | 终止并报告输出超限、结果不完整 |
| 插件 stdout 协议 | 保序并保留约定未消费范围 | 施加背压，超过约定期限／容量后终止，不静默丢字节 |
| 诊断日志 | 有界保留、可轮转 | 继续运行并标记丢弃区间 |

插件 stdout 与 stderr 可采用不同政策。Guardian 持续读管道的责任独立于 Node 连接与宿主存活，
政策触发状态必须可查询。有界 I/O 是正确性边界，不扩展为通用运行配额。

### D2：续读显式表达缺口和完成阶段

读取使用序号或偏移，历史已淘汰时返回缺口。管道 EOF、数据已持久化、输出中断和截断分别表达，
不能把 EOF 等同于完整可读。承诺持久的可读偏移受
[数据先于元数据提交](../persistence/0-independent-journals-and-responsibility-retirement.md)约束。
输出可续读不等于插件会话已恢复。

### D3：输入保序、去重，并在写入时验权

分别表达运行层已接受、字节已写入 OS 管道和插件已处理命令；最后一项只有业务协议能证明。
输入在可核实记录范围内按身份去重，同身份不同数据拒绝。实际写入也检查有效控制权；撤权完成
后不得继续交付旧队列中尚未写入的字节。

写入后落盘前崩溃时交付未知，不自动重发。已进入管道的字节无法撤回，新控制者接管保留运行时
必须通过插件协议对账此前命令。可靠业务重试由插件协议和 Node 决定，不能由管道层猜测。

### D4：输出拥塞不阻塞控制

使用[独立 Control／Events／I/O 流](../protocol/0-independent-local-streams-and-state-recovery.md)，
分离读写任务和队列，不持有控制状态锁等待 I/O。独立连接本身不是证明，必须在输出积压、读者
离线和通道断线时验证续租、撤权、停止仍可推进。

## 不变量

1. 输出丢失或截断可观察，协议字节不静默淘汰。
2. 输入交付未知不被自动重发或改写成未交付；已写入不等同于业务已处理。
3. 撤权阻止未交付旧输入，输出拥塞不拖延控制权检查。

## 为什么不是这些替代方案

| 方案 | 取舍 |
|---|---|
| 所有输出统一无限缓存 | 读取方便，但消费者离线可耗尽内存或磁盘 |
| 所有输出统一丢弃旧数据 | 空间有界，但会破坏插件协议和 Git 结果解释 |
| 回复丢失就重发 stdin | 传输恢复简单，但可能重复已经处理的业务命令 |

## 落地与验收

早期切片即实现基本管道读取和写入验权，再补齐输出政策、续读与交付恢复。覆盖宿主强杀期间
输出、协议背压、日志淘汰、stdin 写入后记录／回复丢失及撤权竞争；逐通道证明完整性与控制可用性。

## 本决策未解决的问题

输出阈值、背压期限、保留范围、输入去重耐久范围及敏感输入持久化政策需冻结。插件业务会话的
接管协议由插件领域制定，本 ADR 只承诺可核实的字节交付事实。
