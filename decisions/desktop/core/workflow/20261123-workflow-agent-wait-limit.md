# 工作流 Agent 单次发送默认按进展等待，超长静默须显式选择

工作流 Agent 的 `wait` 从本次实际发送或最后一次可归属进展起计时，连续静默 30 分钟后结束本轮。确需容忍长时间静默的 Desktop 节点可显式选择 `unbounded`。Desktop 已实施该策略，重新挂载的隔离边界见下文。

## 继承与修改

| 前序约定 | 处理 | 行为 |
| --- | --- | --- |

| 同一 ADR 的 D2–D4 | 继承 | 保留冻结配置、取消、真实失败、会话隔离和诊断。 |
| [交互式节点首轮停靠：首次自动回合需显式确认，异常停靠与等待参与分开显示](20261102-first-turn-confirmation.md) | 修改 | 将有限 `wait` 到期纳入现有自动首轮失败与人类回合异常停靠的分类。 |
| [交互式节点按最终尝试的有效产出恢复](20261118-interactive-retry-output.md) | 继承 | 仍以最终发送的产出判定交付。有限等待到期不创建静默重发边界。若 stale-load 恢复发生重发，仍按既有规则隔离各次发送的产出。 |

## D1　配置与计时边界

| `agentConfig.promptInactivity` | Desktop 行为 |
| --- | --- |
| 缺失、`null` 或 `"timeout"` | 既有超时重发策略。普通聊天沿用相同策略。 |
| `"wait"` | 从每次实际发送起计满 30 分钟。只有 D2 的进展能续满同一个窗口。运行详情按冻结值显示「持续等待，无进展 30 分钟后失败」。 |
| `"unbounded"` | 无 prompt 静默期限。编辑器标明「无限等待（需手动停止）」，运行详情展示冻结选择。 |

其他值在执行前拒绝。打开图或修改无关字段保留原字段。已发布图和运行快照无需迁移。升级 Desktop 会重启服务进程，在途回合随进程结束；重启恢复后的下一次实际发送按恢复后运行快照中的 `promptInactivity` 解释（恢复时没有切换快照的，即原冻结值）。旧 Desktop 拒绝新取值。Cloud 的发布门禁继续拒绝非 null 的 `promptInactivity`。

## D2　只有本轮可归属的信号续期

| 信号 | 续期条件 |
| --- | --- |
| 消息或思考 | 本次发送收到非空内容。 |
| 计划 | 父会话与各个可归属子代理分别维护本次发送的计划，按同一来源比较。与该来源上一次所见计划相比，条目内容、顺序、优先级或状态变化。重复计划或仅 `_meta` 变化时保留原截止时间。 |
| 父工具 | 第一次报告状态、状态变化，或 `content`、`rawOutput` 有非空变化。比较基准是同一工具本次发送中上一次所见的对应字段。重复值和只改 `title`、`kind`、`locations` 的更新保留原截止时间。 |
| 子代理 | 能关联本次发送中仍为 `pending` 或 `in_progress` 的具体委托，并满足上述内容或状态变化判据。CodeAgent 使用[子代理更新通道 D6](../../../node/agent-runtime/20261118-codeagent-subagent-update-channel.md#d6父委托未结束时指向它的子代理帧为父窗口续期但不暂停计时)的父 `toolCallId`。仅定位到父会话、找不到本轮委托或委托已结束的更新均保留原截止时间。 |
| 自动权限应答 | 仅在确认请求属于本轮父工具且应答成功写入后续期。来源不明时保留原截止时间。写入期间按原截止时间计时。子代理权限应答只证明子代理权限交互完成，不能作为父工具进展。 |

会话级通知、`usage_update`、load 回放、stderr、其他会话的活动，以及表中未列出的未知或扩展通知均保留原截止时间。工具持续运行、等待授权和处理授权时，静默计时持续进行。

## D3　到期、取消与节点结果

先确认已就绪的本轮正常响应或已受理的显式取消，再处理同一轮就绪的到期。对与定时器同时待处理的有效进展，按到达时间判断。进展在原截止前到达时从到达时刻续期，达到或超过截止时间时到达则不能续期。处理到期后，以静默超时作为本轮终态，迟到的正常响应或取消不会改写结果。显式取消先受理时沿用用户停止归因。验证须覆盖同刻正常响应和到期，以及显式取消在到期前后两种顺序。

到期后取消本次 provider 请求及未决权限交互，在既有取消宽限内等待终态。取消终态已确认的会话可继续使用。宽限内未收敛时隔离旧发送，后续回合走现有恢复流程，旧更新不能进入新发送；取消未确认后，在同一连接上重新挂载原 provider 会话的路径尚未满足此承诺，见实施边界。当前回合及订阅者以可辨识的静默超时结束。节点失败策略在旧发送终止或被隔离后接手。

| 回合 | 到期结果 |
| --- | --- |
| 非交互节点 | 本次尝试失败，按节点策略决定是否重试。 |
| 交互节点自动首轮 | 节点直接失败，释放首轮执行会话。此路径不创建停靠快照，也不触发节点重试。 |
| 交互节点人类回合 | 保留工作流会话与历史，节点停靠为 `abnormal`，`stopCause = prompt_timed_out`，等待用户继续或显式强制完成。没有自动节点重试。 |

不会因静默重发本轮 prompt。既有 stale-load 重建重发保留。真实断连、取消和工作流停止仍可结束两种等待，建立会话及取消宽限仍各有期限。诊断继承旧 D4，记录实际策略、会话和发送归属、尝试、窗口、静默时长、运行中与待执行工具数、终止原因和取消结果；不记录模型内容或工具参数，也不从静默推断子进程已退出。

## 不变量

1. 每次实际发送使用所属运行的冻结策略，有限等待从本次发送或 D2 的最后一次进展计时。
2. 静默到期最多结算一次，失败策略接手前旧发送已终止或被隔离；取消未确认后同一连接重新挂载原 provider 会话的迟到流量不在此保证内，见实施边界。
3. 无限等待只能显式选择。两种等待均保留真实故障、取消和停止路径。
4. 交互节点的自动首轮与人类回合分别进入既有失败和异常停靠路径。
5. 两种等待都不因静默重发本轮 prompt。
6. 只有 D2 清单内可归属本次发送的有效进展才能续期。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 节点自定义 `{"waitMinutes": N}` | 允许超长窗口会绕过无限等待选项上的手动停止提示。固定 30 分钟配合显式无限等待，能清楚区分两种行为。 |
| 父工具只有状态变化才续期 | 工具持续产出且状态不变时仍可能到期。有限等待在工具执行时继续计时，因此需要识别非空内容变化。既有 `timeout` 在工具运行时暂停计时，对不带状态的工具更新续期。本 ADR 的内容过滤仅适用于有限 `wait`。 |
| 继续让旧图无限等待或按总时长终止 | 前者保留已知挂起路径，后者会中止持续报告进展的长任务。 |
| `waitForever`、`0` / `null` 哨兵、`manual` | `unbounded` 与旧 `wait` 区分明确。哨兵会与默认值或分钟数混淆，`manual` 容易被读成等待人工输入。 |

## 实施边界

[Desktop #803](https://github.com/ora-space/desktop/pull/803) 已合并。[四组核心用例](../../../../test-cases/desktop/core/workflow/prompt-inactivity.md) 按固定产品版本记录验证结果。取消未确认后，同一连接重新挂载原 provider 会话仍可能收到旧回合的迟到更新和权限请求。该路径与既有超时和显式取消恢复共用，由 [#1392](https://github.com/ora-space/circus/issues/1392) 单独承接，对应隔离义务为 `Partial`。

Desktop 升级后启动时按既有规则清理中断的节点：外层节点在显式恢复时开启新的节点尝试；复合区域内被中断的轮次由复合节点吸收，结算为失败轮。跨版本恢复后首次实际发送仍缺冻结策略的直接证据，由 [#1421](https://github.com/ora-space/circus/issues/1421) 验证。Cloud 混合版本支持及无法归属具体委托的 provider 适配另行处理。
