# Skill 配置通过宿主启动环境快照交付，敏感字段按声明脱敏

> 历史决策：[Skill 按存储路径以会话清单交给 Agent](../../../core/agent/session/skill/0-skill-catalog-from-storage-paths.md)（`approved`）取消 Skill 物化。正文中“Effect 物化”“Skill 内容仍正常物化”“无配置的 Skill 继续物化”改读为 Skill 仍进入会话清单；配置交付规则不变。

静态 Skill 插件用 `assets/config.json` 声明配置，通过宿主启动时冻结的环境快照交付给 Agent 进程树。敏感字段不回传编辑器；公开字段正常显示。本 ADR 记录 Desktop 已落地的配置契约；实现与代表性直接证据见对应核心用例。

| Skill 脚本配置交付 | 新增；仅 Desktop 宿主配置，不扩展 Cloud 或普通导入 Skill |

## D1：配置沿用通用存储，增加敏感字段声明

Settings-only 配置中的每项 Setting 可声明 `secret: boolean`，省略为 false；字符串、数字、布尔值都支持。字段参与声明指纹，现有 revision CAS、声明变化冲突、必填判断、默认值和重置机制保持不变。

本决策将 `secret` 限于 v1 Settings（包括 Skill、MCP），不扩展已发布的 v2 Agent 声明。v2 Agent Setting 拒绝 `secret` 成员，包括显式 `false`，其编译输出与指纹契约保持不变；若要支持，需要另行修改 Agent 声明契约。该兼容边界已批准。

secret 字段的默认值、存储值、有效值在编辑器响应中均为空，只返回来源与 redacted 标记。未编辑时保存保留原值；显式重置该字段删除存储覆盖。公开字段仍可见。MCP 即使省略 secret 仍全量脱敏。

配置仍保存在宿主插件数据目录的 `store.json`，采用明文存储，`secret` 只做界面脱敏，不是加密。插件作者不得在发布包的默认值或说明中放置真实凭据：脱敏不能撤销包本身的公开内容。

## D2：完整配置在 Desktop 启动时冻结为全局环境快照

每次 Backend 初始化从已安装有效 Skill 插件及宿主配置建立不可变内存快照。Agent 插件启动和宿主 childprocess/spawn 使用同一快照，包括不指定 cwd 的子进程。非 Agent 插件不获得注入。

配置缺失必填值、损坏、非法或含 NUL 时，整包不注入，不阻止其他插件或会话启动。可选缺失值不产生变量。配置状态仍由原配置入口展示；宿主诊断不包含配置值。Skill 内容仍正常物化，脚本负责报告缺少配置。

快照对所有 Agent 和工作区共享。这是用户信任本机 Agent 的执行边界，不是按 Skill 或工作区授权的凭据代理。Agent 和脚本能够自行读取并输出值；宿主无法承诺第三方脚本不会泄漏。

## D3：变量名采用可读规范化，检测撞名并保留宿主前缀

变量名为 `ORA_SKILL_<PLUGIN>_<FIELD>`。PLUGIN 使用含 namespace 的完整 canonical Plugin ID，FIELD 使用 Setting ID；分别按以下规则规范化，再用单个 `_` 连接：

1. ASCII `a`–`z` 转为 `A`–`Z`，ASCII `A`–`Z`、`0`–`9` 原样保留。
2. 每个其他 Unicode 码点（标量值）分别替换为一个 `_`，不做 NFC、NFD 等 Unicode 规范化，包括 namespace 的 `/`、标点、空格、非 ASCII 字母和数字；不使用 Unicode 大写转换。
3. 不合并连续 `_`，不裁去首尾 `_`。例如 `a/b` 和 `api-token` 得到 `ORA_SKILL_A_B_API_TOKEN`；`a//b` 规范化为 `A__B`，`é`（单码点 U+00E9）规范化为 `_`，`e` 加组合重音 U+0301 得到 `E_`。

这是有损命名：易读且便于脚本直接使用，唯一性由检测而非编码保证。建快照时先对已安装有效 Skill 插件的有效配置声明中全部字段派生变量名，再按 ASCII 大小写不敏感分组检测撞名；字段是否有存储值、默认值或有效值均不影响参与检测。配置值缺失、损坏、非法或含 NUL 而被跳过的插件仍参与检测；插件本身或配置声明无效、无法取得有效字段集合时不参与。撞名检测先于配置值注入资格判定，可选字段缺失仍参与检测，但不产生环境变量。跨插件、同一插件内不同字段，以及插件与字段连接处的歧义都算撞名。例如 `x/a_b` 的 `c` 与 `x/a` 的 `b_c` 都得到 `ORA_SKILL_X_A_B_C`。

任一撞名涉及的插件整包不注入，包括其未撞名字段；诊断可指出插件、字段和变量名，但不得包含配置值。不静默覆盖、不按枚举顺序选择胜者，也不因移除一个冲突插件而让另一个冲突插件重新取得资格。其他无冲突插件正常注入。

字符串原样交付，数字采用 JSON 表示，布尔值为 `true`/`false`。变量名由宿主派生，不允许插件声明 `GITHUB_TOKEN` 之类无前缀的通用名或自定义别名，以免覆盖用户原有环境并影响无关工具。

Agent 插件启动及宿主 `childprocess/spawn` 创建子进程前（包括不指定 cwd 的路径），对继承环境和调用方 `env` 中大小写不敏感匹配 `ORA_SKILL_` 前缀的变量先全部移除，再注入同一宿主快照；空快照或跳过插件时也执行清理。调用方不能覆盖、伪造或复活已跳过的变量。

## D4：修改在重启 Desktop 后生效

保存、重置、安装、更新和卸载不改变当前快照。即使之后重新启动单个 Agent，也仍使用本轮 Desktop 的快照。设置页明确提示重启 Desktop；宿主不自动停止活动会话。

这避免直接 spawn 与宿主代 spawn 使用不同版本，但意味着撤销或卸载后旧进程仍能持有凭据。需要立即撤销时，用户必须终止相关进程并在外部服务吊销凭据；重启只刷新宿主交付，不是服务端吊销。

## 为什么不是这些替代方案

| 方案 | 取舍 |
| --- | --- |
| 全量脱敏 | 更简单，但 URL、环境名等公开配置也不可查看 |
| 工作区 .env | 通用脚本容易读取，但增加误提交、同步与备份泄漏面 |
| 按工作区隔离或即时更新 | 共享 Agent 插件进程不能表达该边界，需要另行设计执行或代理通道 |
| 凭据查询 Tool | 可按需授权，但要求脚本改用宿主接口，不适合作为本期通用交付路径 |
| UTF-8 大写十六进制变量名 | 虽可无损区分身份，但要求脚本借助生成函数适配；撞名少见，采用可读命名加检测与整包拒绝，以保留脚本易用性 |

## 已知边界

- `store.json` 明文保存配置，损坏备份也不提供加密保护。`secret` 只做界面脱敏，系统钥匙串留待以后。
- 所有 Agent 及其子进程都能读取全部完整配置的 Skill 变量；安全边界是用户信任本机 Agent，不按工作区隔离。
- 安全承诺只覆盖宿主自己的配置交付路径。脚本自行打印后，值会进入 ACP 消息、插件日志、debug 构建的 TRACE 日志和会话 JSONL；界面脱敏不阻止这些泄漏。
- 卸载、重置和保存不会撤销当前快照或已交付到进程的值；立即撤销须终止相关进程并在外部吊销凭据。

## 不变量与验收

1. 宿主的配置交付路径不将配置值写入工作区、Effect、ACP 消息或日志；此承诺不覆盖 Agent 或脚本自行输出值。脚本输出可能进入 ACP 消息、插件日志、debug TRACE 日志和会话 JSONL，界面脱敏不能防止这些泄漏。
2. 敏感字段不通过读取、保存、重置响应返回；MCP 保持全量脱敏。
3. 两条 Agent 启动路径消费同一快照，配置变化仅在重启 Desktop 后进入快照。
4. 无效配置整包跳过；无配置的 Skill 继续物化，其他 Agent 和 Skill 不受影响。
5. 变量撞名按大小写不敏感检测，涉及的插件整包不注入；继承环境和调用方 env 中的保留前缀先移除再注入。

[核心用例](../../../../../test-cases/desktop/plugin/category/skill/configuration-and-startup-environment.md)固定配置保存与脱敏、跨进程注入、规范化和撞名整包拒绝、保留前缀清理、NUL、缺失必填值、重启更新和卸载边界的验证义务。证据固定到已合并的 Desktop 提交；尚未完整覆盖的组合义务保留 Partial，不将分层测试等同于完整交互验收。

## 落地顺序与未解决的问题

配置声明、编辑器脱敏、启动快照和两条进程交付路径已在 Desktop 落地。旧配置无需迁移；带 secret 的新声明不保证可被旧版本宿主接受。工作区隔离、运行时热更新、系统钥匙串、Cloud/远程执行及普通 Skill 导入配置留待后续决策。
