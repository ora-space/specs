# 插件分发：pack 从源检出本地安装，隐藏成员只退出新构建的展示索引

registry 保持“源检出是事实来源，索引是展示缓存”。普通插件的隐藏 listing 在新构建索引中
被过滤，但按 ID 解析和安装继续访问源检出。pack 没有下载资产，宿主从所属源的 registry 清单
本地创建安装态，其成员仍按同源的既有资产获取方式安装。

本 ADR 为 `approved`，已完成评审，尚未实现，细化已批准的
[Plugin Pack 根决策](../category/pack/0-plugin-pack.md) D1–D4、D9。涉及 `ora-plugin-registry`
的构建与解析、manager 的安装来源选择、backend 的可安装性投影和前端入口；字段规则由
[清单配套决策](../manifest/20260915-pack-manifest-and-marketplace-visibility.md)拥有。
重试、持久状态、归属与回滚仍由 pack 根决策负责，不在 registry 中复制。

本决策不移动源检出，不改变 namespace 或 Source 获取配置。可见性过滤不改变缓存格式或版本；
只有仍满足当前格式和版本要求的旧缓存才允许暂时保留隐藏条目。

## 继承与修改

本决策直接继承本链前序
[Source 级插件包获取决策](20260904-source-configured-artifact-retrieval.md)，在其继承的
[分发根决策](0-registry-distribution.md)与
[Namespace 决策](20260831-source-derived-namespace.md)上增加分发形态，并与跨领域的
[图标资产决策](../manifest/20260909-plugin-logo-as-themed-asset.md)协调缓存边界。

| 前序约定 | 本决策 |
| --- | --- |
| Git 同步提供元数据，源检出是事实来源 | 继承，不变；pack 清单与成员清单均来自绑定源 |
| namespace 绑定唯一 source，裸 identifier 在该源内解析 | 继承，不变；成员 ID 由 pack namespace 与成员 identifier 组成 |
| 有效 listing 进入派生索引 | 修改：普通插件的隐藏 listing 在生成展示条目前被过滤，源内解析不受影响 |
| 无下载资产的 listing 在当前 host 不可安装 | 修改：pack 可本地创建，普通无资产 listing 仍不可安装 |
| 安装 resolve 后按 Source 获取方式选择和下载制品 | 修改：pack 分支本地创建，只有普通插件及 pack 成员进入下载链路 |
| Source 拥有 Direct HTTPS / S3 SigV4、代理和凭据边界 | 继承，不变；pack 不引入第三种 Source 配置，成员不绕过既有认证与校验 |
| 索引原子写入，打开市场只读缓存 | 继承，不变；可见性本身不增加启动同步或前端过滤 |
| 图标格式变化提升索引版本，不可读缓存降级为空目录 | 继承，不变；旧缓存可保留仅适用于仍能加载的缓存 |

## 决策

### D1：展示过滤和源内解析分别服务各自的用途

构建器解析源清单后，在生成展示索引条目之前排除普通插件的 `marketplace_visible = false`
listing。有效但隐藏的条目不作为损坏清单报告；解析非法清单仍沿用既有跳过与诊断行为。
pack 禁止该字段，合法 pack 按正常规则进入索引。

源内路径选择、同源身份判定及去重顺序继续使用 registry 所有者的既有规则，不能因展示过滤使
索引与 resolve 对同一 ID 选中不同的源条目。成员解析、README 或图标按 ID 读取不借用展示索引
作为允许列表；隐藏不等于访问控制，也不会隐藏已经安装的插件实体。

按新规则生成的浏览、搜索与详情入口不再产生隐藏 listing；保留旧入口或已知 ID 的调用仍可
访问源条目。它们的安装继续执行正常清单、host、来源和包校验，不因隐藏状态放宽条件。

### D2：pack 可安装性由 kind 表达，不伪造通用下载资产

索引保持既有 `kind` 与 `release_targets` 的职责：无下载资产仍表示没有发布资产，不能给 pack
伪造 URL、摘要或通用资产目标来通过普通插件判定。可安装性投影在同一领域所有者中按 kind 区分：

| listing | 展示与安装语义 |
| --- | --- |
| 合法 pack、无下载资产 | 展示本地可安装入口；实际成员可行性在 pack preflight 验证 |
| 普通插件、无下载资产 | 保持既有“没有可下载 release”不可安装结果 |
| 普通插件、有通用或 target 资产 | 保持既有 host 选择与兼容性结果 |
| 隐藏普通插件 | 不进入新索引；按 ID 安装仍遵守普通插件规则 |

pack 入口可用只说明宿主支持这种本地创建方式，不保证所有成员可安装。索引不递归解析成员，
也不缓存聚合兼容性；缺失成员、嵌套 pack 与待安装成员的 host 不兼容由无副作用的 preflight
返回 typed 错误。已安装任意版本而跳过的成员不需要 registry 新版本的资产兼容性。

由 `kind` 已能推导的本地安装能力不增加另一份手写缓存标志。前端消费统一的领域投影，不根据
`release_targets` 自行复刻 pack 例外；普通插件的 host 判定保留。

### D3：pack 读取本地清单，成员复用 Source 获取与包校验

安装先由 canonical ID 的 namespace 定位 source，再读取其 registry 清单。pack 分支在任何
成员制品请求前建立本地安装态与恢复记录；不进入 HTTP/S3 下载、不签名 pack 请求，也不对
本地清单伪造下载摘要。Git 源同步与本地复制是不同动作，已有本地检出上的安装 preflight
不隐式同步源；缺少源或条目时报告错误，不跨源兜底。

成员仅使用裸 identifier，完整 ID 继承 pack namespace。解析直接访问相同 source，固定本次
计划及所选 release，再委托单插件获取与安装接口。Direct HTTPS / S3 SigV4 的相容性、代理、
摘要、target 自述、解包限制与生命周期清理全部继承；认证成功也不能代替内容校验。

本地复制只消费 pack 清单，不递归复制 registry 目录，也不带入源提供的安装记录。registry
保持只读；`installed/<ns>/<identifier>/staging/` 的创建、归属校验和版本扫描隔离由安装
所有者按 pack 根决策负责，源扫描和缓存清理均不得写入或清理该目录。

图标继续按图标 ADR 从各自根读取：marketplace 使用 registry 根，已安装条目使用 installed
根。只复制清单的 pack 可以在已安装列表使用无图标回退；本决策不从 registry 回退读取 installed
图标、不添加远程图标，也不通过图标系统向包目录写入字节。

### D4：刷新原子替换新索引，可读旧缓存可暂留隐藏条目

可见性字段不写入索引，不提升缓存版本，也不要求每次读取缓存时重新解析全部源清单。旧索引只要
仍满足当前版本和格式要求，就可在刷新前暂留隐藏条目；刷新成功后原子替换为新规则构建的索引。
刷新失败不删除已有缓存，重启后按现有加载规则使用它。

该容忍不覆盖类型不符、版本不匹配或损坏的缓存；图标 ADR 已要求这些情况降级为空列表与
`updated_at = 0`，并等待显式同步。打开市场仍不触发网络，也不为了隐藏条目额外作废可读缓存。
因此两条承诺可以同时成立：可见性变化无需缓存迁移，独立的索引 schema 变化仍执行既有失效策略。

## 为什么不是这些替代方案

| 方案 | 否决理由 |
| --- | --- |
| 前端接收全部 listing 后过滤 | 所有消费者都需转发和理解字段，且展示策略在多层重复 |
| resolve 只查索引 | 隐藏成员无法安装，把展示偏好变成了分发拒绝 |
| 给 pack 伪造通用资产 | `release_targets` 不再描述发布资产，安装分支可能误入下载链路 |
| 为本地 pack 增加 Source 获取模式 | Source 模式决定普通制品如何获取；pack 与下载成员共存于同源，不是另一个认证配置 |
| pack 自身下载，成员成功后最后安装 | 重建根决策已排除的孤儿窗口与第二份制品事实 |
| 可见性变化一律作废旧缓存 | 展示偏好不值得造成刷新前空市场；当前格式不变，可以安全保留可读缓存 |
| 为保留隐藏条目兼容所有历史缓存格式 | 绕过图标 ADR 的类型与版本检查，可能让整个市场读取失败 |

## 不变量

1. 新索引排除隐藏普通插件，源内解析、成员安装和已安装实体仍可用。
2. 合法 pack 本地可创建，普通无资产 listing 仍不可安装，二者不伪造相同的资产状态。
3. pack 与成员始终使用绑定 source；同名跨 namespace 条目不兜底、不混用认证配置。
4. pack 本地创建不下载制品；成员保留全部 Source 获取、摘要与包校验规则。
5. 可读旧缓存可暂留隐藏条目，成功刷新才原子替换；不可读缓存遵守既有降级规则。
6. 索引和图标读取不改变安装树，不触碰 pack 持久状态目录。

## 风险、兼容与未决项

- 旧宿主拒绝未知 pack kind，但仍显示忽略可见性字段的普通成员；不通过版本探测改变源内容。
- 索引的 pack 可安装性不是成员兼容性承诺，成员失败必须在 preflight 向用户解释，而不是在
  下载中途才发现。安装前预览与聚合兼容性缓存不在本决策范围。
- 不直接重写已有索引或删除安装文件：前者只在成功重建后替换，后者的冲突、旧试验数据识别和
  持久状态恢复由 pack 根决策 D9 负责。不存在从 `data/` 自动批量迁移的隐含授权。
- 插件更新策略、跨源依赖与远程发布工具留待后续 ADR；不借本地 pack 分支修改它们。

## 落地顺序

1. **验证基线**：按已批准的清单与来源边界建立真实源和缓存场景；完成条件为下列 registry
   核心用例的义务可逐项验证，不将既有单插件测试作为新分发行为的完整证据。
2. **索引与投影**：实现构建过滤和 kind 驱动可安装性；完成条件为隐藏 resolve 不受影响、普通
   兼容性不变、可读旧缓存保留且新索引无隐藏条目。此阶段不单独开放未完成的 pack 安装链路。
3. **安装组合与集成**：连接 pack 本地准备和成员下载接口；通过生产接口验证零 pack 制品请求、
   同源认证、成员校验与失败回滚。与完整编排及前端通知一起开放能力，Source 配置保持不变。

本领域核心用例见
[本地 pack 与隐藏条目分发](../../../../test-cases/desktop/plugin/registry/local-packs-and-hidden-listings.md)，
新增行为的直接证据当前为 `Missing`。跨领域能力验收见
