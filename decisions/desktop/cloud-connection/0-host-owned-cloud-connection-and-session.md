# Desktop 宿主拥有 Cloud 连接、信任与会话，本地工作独立可用

Desktop 宿主直接管理可配置的自建 Cloud 连接及认证生命周期，凭据绑定部署签名身份与账号，
通过系统浏览器与 Gateway 完成登录。本地工作不依赖 Cloud 登录或在线状态；首版每个安装实例
同时只有一个活动 server 和账号，多窗口共享选择。

本 ADR 为 `approved`：架构选择已批准，尚未实现。它建立 Desktop 的 Cloud 连接根边界，
不复用已退役的 Client–Controller IPC 决策。认证与会话协议的唯一权威见
[Gateway 原生会话 ADR](../../cloud/identity-access/20261019-deployment-bound-desktop-sessions.md)。
现有本地文件、模型连接、Agent 凭据和 Git 身份不迁移，既有浏览器会话不转成 Desktop 会话。

## 问题与约束

自建部署有独立地址、证书、升级节奏和会话政策。通过官方认证插件推送地址或协议变更，无法让
各部署同时升级；把 URL 当身份又会在迁移时丢失会话，或把凭据发给接管旧地址的其他部署。
宿主必须拥有完整的连接、信任与认证责任，Cloud 不可用也不能使本地开发现场失效。

## 决策

### D1：Cloud 状态只约束依赖 Cloud 的能力

未配置 server、未登录、离线、Cloud/认证故障、证书/版本不兼容、会话过期或账号停用时，
本地启动、Agent、编辑、工作区与本地运行照常可用。探测、恢复、续期异步执行，不阻塞启动。
本地 Agent 继续使用自己的模型连接和凭据。

账号区域显示 server、账号和连接状态；云端入口就地提供配置、登录、重试、修复或切换操作，
不为本地操作反复弹登录窗口。连接失败、会话失效、账号停用、资源无权限分别表达；普通资源
`403` 不是账号停用信号。无空间沿用创建/加入引导。

### D2：一个宿主协调器拥有全部生命周期

宿主拥有 server 配置、传输与部署信任记录、登录事务、浏览器入口、回调校验、换票、
系统安全存储、恢复、续期、退出、账号状态和云端订阅。多窗口/进程必须协调到唯一事务与
续期所有者，不能各自刷新凭据或建立第二份账号事实来源。

认证随 Desktop 发行升级。没有预装认证插件、不可卸载插件、特权插件或独立认证更新链路。
普通插件与页面只得到所需状态或受限操作，不能读会话凭据。系统安全存储不可用时保留本地
功能并说明修复路径，不降级为明文配置。凭据不进入日志、诊断、浏览器长期存储或回调 URL。

### D3：先验证目标，再经系统浏览器交接

账号设置允许编辑 server 地址，展示规范化地址、协议、部署身份指纹与能力兼容结果。
拒绝 URL 用户名密码、fragment、无关 query，保留部署路径前缀。首次连接先不带凭据探测，
完成传输信任、TOFU 和协议协商后才登录；缺必需能力时指明升级哪一侧，不静默降级。

宿主创建绑定部署身份、公钥、目标地址、随机 state、PKCE S256、回调目标和有效期的事务，
打开该 server 的系统浏览器页面。页面明确目标部署与将使用的账号，并允许切换。Gateway
复用已配置外部登录与已有网页会话，但创建独立 Desktop 会话，不导出网页 Cookie。
回调中的地址永远不能改变换票目标；宿主只访问事务记录的已验证 server。

正式支持 loopback 与 deep link，发起前协商并固定方式，不在事务中任意替换。
loopback 使用回环 IP 和系统分配端口，只监听回环接口，限制路径、事务和接收次数，
成功、取消、超时均关闭监听。Linux deep link 不稳定时可选 loopback。
开发/正式包隔离，多窗口/实例由唯一事务所有者接收回调。

未知、过期、重放、并发重复、跨 server 或绑定不符的回调拒绝；修改登录目标、切换账号或
server 时取消未完成事务。超时或回调失败保留网页返回 Desktop/重试入口，不自动发起循环登录。
loopback 与 PKCE 的依据为 [RFC 8252 §7.3、§8.3](https://www.rfc-editor.org/rfc/rfc8252#section-7.3)。

### D4：传输信任与部署身份分别验证

身份、挑战、TOFU 和迁移的服务端约束见 Gateway ADR D2。宿主记录稳定 deployment ID 与
签名公钥指纹；首次 TOFU 由用户确认，可核对管理员提供的指纹。首次确认本身不能证明预期组织。

| 传输场景 | 宿主行为 |
| --- | --- |
| 系统信任且主机名有效的 HTTPS | 正常验证后使用 |
| 自签或私有 CA 未受系统信任 | 展示地址、证书主体、有效期、SHA-256 指纹；明确确认后固定该端点证书指纹，主机名/有效期异常仍需明确呈现，不能全局关闭 TLS 校验 |
| 固定证书指纹变化 | 暂停请求，展示差异并重新确认；同一部署签名不能豁免证书异常 |
| 显式内网 HTTP | 首次或改地址时提示流量与凭据可能被窃听/篡改、仅在可信内网使用，确认后持续标识 HTTP |
| 浏览器不信任登录页证书 | 提示按部署指引安装受信任 CA/证书后重试；宿主固定不能绕过浏览器安全页 |

身份挑战不加密 HTTP，也不能阻止透明转发，不能承诺与 HTTPS 等价。
宿主不猜测某主机是否“内网”而自动降级协议；用户明确选择 HTTP 不代表旧 Gateway 已支持它。

改地址先验证新端点传输信任，再不带旧凭据验证身份挑战。同 ID、同公钥、能力兼容时关联新地址，
只沿用仍有效的会话；过期仍须重登。不同身份或同 ID 换密钥按新 server 展示差异、明确确认后
重登，旧凭据不得发出。失败保留原配置/信任记录，不要求旧地址在线或官方市场源可用。
HTTP 重定向不授权迁移，带凭据的 API 请求不自动跨源跟随。

### D5：恢复、活动、续期与撤销采用同一上下文

宿主按 Gateway 公布的空闲期限、绝对上限、到期时间、活动节奏和续期方式执行，默认与权威
判定见 Gateway ADR D4–D6。前台操作、编辑、前台查看/等待运行中的 Agent 算活动；后台心跳、
续期自身、休眠、无人查看的后台任务不算。汇总上报，不收集键鼠内容。

活动上报只代表正常客户端的观察，不能声称服务端验证用户在场或识别恶意伪造。
休眠、崩溃、多窗口与网络恢复走同一续期所有者和有界轮换恢复协议；网络/5xx 不误清凭据。
启动、唤醒与恢复网络先复核再恢复云端操作，复核不计活动，不自动重放消息或创建任务。

在线有云端连接时，撤销/停用检测与长连接复核至多 60 秒；到已知到期时间即停止使用。
离线只能显示标记离线的缓存，不能假称已确认远端撤销。无法按时复核时停止云端使用并展示
连接状态；只有明确会话失效才转成重登，不把故障当退出。

### D6：切换与退出隔离私有状态，保留本地现场

凭据、私有草稿、缓存、订阅和迟到响应以部署签名身份与账号隔离。同身份改地址按 D4 处理，
不是切换账号。切换账号或不同部署先展示影响，确认后撤销当前 Desktop 会话、清本机凭据
与账号私有缓存、终止旧连接/订阅、取消登录事务，再进入目标信任与登录。新登录失败仍可本地
工作，旧目标可重新登录，但不自动恢复已清理凭据。

迟到的旧响应不得写入新上下文。被动过期/撤销/停用仅解除云端访问，保留本地文件、工作区、
编辑与未发送内容，标注原上下文；同身份同账号重登可恢复仍保留的现场，不自动上传给新账号。
显式退出清账号私有缓存，不删除本地工作文件；未发送本地内容保留原归属，不作为新账号缓存。

退出不退出浏览器或 GitHub，不改本地 Git 作者、模型 Key 或 Agent 凭据。不主动取消已启动的
服务端任务，任务依原授权和生命周期推进，不保证成功；前端断连不等于任务取消。
断网退出清本机状态并明确“已退出此设备，服务端撤销未确认”，不留完整访问凭据作撤销队列。
网页与各 Desktop 会话独立退出、独立计算活动，多设备登录不互踢。

## 不变量

1. Cloud 失效不会成为本地启动、编辑或 Agent 运行的额外门槛。
2. 只有宿主拥有会话秘密和登录事务，插件不得获取账号凭据。
3. 旧凭据只发送给传输信任通过且部署签名身份匹配的目标。
4. 一个安装实例的全部窗口只共享一个活动 server/账号与续期所有者。
5. 未通过恢复复核不得重新发云端操作，恢复本身不产生新业务副作用。
6. 保留的本地现场不会隐式进入另一个 server/账号。

## 为什么不是这些替代方案

| 方案 | 优点与未采用原因 |
| --- | --- |
| 独立更新认证插件 | 可单独发版，但无法替自建部署协调升级，另增特权与不可卸载边界 |
| URL 命名凭据或重定向自动迁移 | 简单，但地址变更会丢身份，旧地址接管/跨源跳转可泄露凭据 |
| 登录成功后解锁整个 Desktop | 入口统一，但云端认证故障会阻断独立本地工作 |
| 同时连多 server | 可并行跨部署，但扩大多窗口选择、缓存、订阅与错误恢复状态空间，首版不做 |
| 宿主忽略证书即可让浏览器登录 | 部署容易，但宿主不能代替浏览器信任，不提供绕过浏览器的承诺 |

## 落地顺序与未解决边界

阶段按 Gateway ADR D7 共用，不能分别宣称两个协议已经完成。第一阶段也必须具有稳定身份、
回调绑定和本地独立的安全前提；阶段未支持的能力明确禁用或指明升级方向。

最低兼容 server 版本按首个实际交付能力的发布版本确定，未发布前不编造版本号。
认证协议字段、OS 安全存储适配和轮换恢复契约必须在实现前完成契约评审；新增架构选择另经
后续 ADR，不因本根 ADR 的 `approved` 自动批准。没有这些契约不能将第一阶段标为完成。
本 ADR 不新增同步、通用离线队列、隐式上传、设备管理、多 server 并行、组织配置、密钥自动轮换，
也不扩展私仓或模型授权。登录仅恢复同部署同账号下已有且明确启用的能力。
