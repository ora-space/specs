# 插件运行日志能力实施指导

本文件指导 `specs/plugin/1-capability.md` 中 `logs/` 与
`permissions.plugin_logs` 的实现。它描述实施范围和验收标准；目录布局、权限语义
和安全边界以主规范为准。

## 目标

为插件提供受 Ora 宿主管理的运行日志能力，同时保持以下边界：

- 插件只能写入自己的日志，不能直接取得宿主文件系统权限；
- 插件日志与插件持久化数据、安装制品和 Ora 自身日志相互分离；
- 日志输出不会因为插件提供了路径或任意字段而扩大权限范围；
- 日志中不能持久化 Secret、凭据或其他不受控的敏感信息。

## 存储布局

实现插件日志根目录：

```text
~/.ora/plugins/logs/<namespace>/<plugin_name>/
```

目录必须由 Ora 创建和管理。插件不得通过 Deno 文件 API 直接访问该目录，也不得
自行拼接宿主路径。日志目录至少要能按插件身份隔离；日志文件是否进一步按版本、
运行实例或日期拆分，由 Ora 的日志实现决定。

`logs/` 不是 `data/` 的别名：日志只用于诊断，不得作为插件状态恢复、配置存储、
缓存索引或业务数据的权威来源。清理日志不得影响 `installed/`、`data/` 或
`store.json`。

## Manifest 权限

在 `orax.toml` 中支持：

```toml
[permissions.plugin_logs]
write = true
```

`write` 的默认值为 `false`。该权限只允许插件通过 Ora Logging SDK 追加自己的
诊断事件，不允许：

- 读取、修改或删除日志文件；
- 选择或传入宿主日志路径；
- 访问其他插件日志或 Ora 自身日志；
- 修改宿主日志级别、轮转、保留和清理策略；
- 通过日志字段指定其他插件、版本或运行实例作为目标。

未知字段、非法类型和非法枚举值必须在安装或编译 manifest 时拒绝，不能静默忽略。
非支持日志能力的插件类型不能声明该权限，除非类型规则明确允许。

## SDK 与宿主行为

插件日志 SDK 至少应提供稳定的日志级别和结构化字段。每次调用由宿主绑定：

- 当前插件身份；
- 精确插件版本；
- 当前运行上下文或 Agent 实例；
- 规范化后的日志级别和字段。

插件传入的字段只能影响事件内容，不能改变日志归属或目标路径。宿主负责：

1. 校验插件已声明 `permissions.plugin_logs.write = true`，并检查用户授权和当前
   运行上下文；
2. 创建日志目录和文件，并确保文件权限仅允许预期的本地用户访问；
3. 限制单条事件、字段和值的大小，避免插件耗尽磁盘或阻塞日志系统；
4. 执行 Secret、凭据、完整环境变量、完整命令行、绝对宿主路径和其他敏感字段
   的过滤或拒绝；
5. 负责文件格式、轮转、保留期限、清理和关闭时的资源回收；
6. 在日志写入失败时返回稳定的可诊断错误，但不能因此授予文件系统写权限，也不
   能阻断插件进程和其他宿主资源的回收。

插件附带程序的 stdout/stderr 是否写入插件日志，由进程管理能力单独决定。不能
因为 `permissions.process.stdio` 存在，就默认授予插件读取或修改日志文件的权限。

## 生命周期

- 插件升级默认保留既有日志；日志事件应包含版本或其他足以关联版本的元数据。
- 停用时不应删除日志，除非明确的诊断或清理语义要求这样做。
- 卸载时必须将日志保留与 `data/` 删除分开处理，并通过明确的用户语义决定是否
  删除。
- 日志清理是可丢弃数据清理，不能改变安装状态、配置状态或插件授权状态。

## 验收标准

- `logs/` 出现在插件存储布局和目录职责说明中。
- 未声明 `plugin_logs` 时，插件日志 SDK 调用被稳定拒绝。
- 插件只能写入自己的日志，路径穿越、绝对路径、符号链接和跨插件访问均被拒绝。
- 日志文件不进入安装制品摘要，也不影响插件升级、回滚和数据迁移。
- 日志具备大小限制、轮转、保留和清理行为，且清理不会删除插件数据。
- 测试验证日志不会包含 Secret 明文、凭据、完整环境变量和不受限的原始 stderr。
- 受管进程 stdout/stderr 与插件主动日志的归属和权限边界有独立测试。
- 插件日志失败、插件停用和插件卸载不会导致受管进程或宿主资源泄漏。
